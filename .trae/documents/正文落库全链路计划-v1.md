# 正文落库全链路计划 v1（P0 · 推演→成书 最后一公里）

> 决策已确认：**作者手动定稿**（收束后前端出「定稿入库」按钮）+ **全链路含前端**（阅读台接真）。
> 目标：打通「主笔骨架 → 场景推演 → 收束 → 手动定稿落库 → 按章阅读 → 全书导出」的最小文章创作落库闭环。

---

## 1. 现状与断点分析（Phase 1 探索结论）

### 正文数据流现状

```
graph.render_prose（每回合生成 180-280 字）
  → world.append_event(EventType.text, actor="成文")   # 存进 sim.events
  → service._archive_turn 把 prose 存 sim.turn_archives（TurnArchive.prose）
  → repo.save(sim_id, sim) 整体快照进 simulations.state_json   ★唯一持久化（JSON 快照内）
```

**断点**：收束时 `analyze_scene_close` 只写 `scene.scene_summary`（摘要），正文从未落到 scene/chapter 维度的可查询字段 → 阅读台 ReaderView 纯静态、无导出能力。

### 依赖注入现状（用户问题结论）

API 层是标准 FastAPI DI：`get_repo()` → `Repo()`（每请求新实例，底层 engine 连接池模块级共享）→ `get_service(repo=Depends(get_repo))` → 路由签名 `svc: SimulationService = Depends(get_service)`。测试用 `app.dependency_overrides[get_repo]` 替换。引擎层（DirectorEngine/CharacterEngine）不走 DI，由 service 在调用点直接构造；`SimulationService._graphs` 是类变量（编译图缓存）。本次新增端点沿用同一 DI 模式，**不引入新依赖容器**。

### 既有内存态限制（需顺手修，否则测试不可断言）

`repo.get_scene` 内存态分支直接返回 `_static_scene()`，不查 `_mem` → 内存态下 `save_scene` 写入的 `scene_summary`/`final_prose` 读不回来。修复：内存态先查 `_mem` 再回退静态目录（与 `get_chapter` 的内存态模式对齐）。

## 2. 最小文章创作落库流程（全链路）

```
① 主笔骨架   /maestro「让主笔构思」→ plan → commit（章/场景/伏笔落库）
② 场景推演   /director/:sceneId 播放 → SSE 事件流（think/act/prose_delta）
③ 收束       director_close 汇报卡（场景摘要/伏笔推进）
④ 手动定稿   收束卡「定稿入库」按钮 → POST /sims/{id}/finalize
             → 聚合 turn_archives.prose → 写 scenes.final_prose（幂等覆盖）
⑤ 续写换场   next_scene 自动续推 → 重复 ②③④（每场景一份定稿正文）
⑥ 按章阅读   阅读台 GET /chapters/{id}/prose（聚合该章全部场景正文）+ 翻章
⑦ 全书导出   GET /books/{id}/export → markdown 文件下载
```

回退重演：rewind 后重新推演收束 → 再次点「定稿入库」→ final_prose 覆盖（幂等，与 MVP 重演原则一致）。

## 4. 接口契约（对好接口）

| 方法 | 路径 | 请求 | 成功响应 | 失败 |
|---|---|---|---|---|
| POST | `/api/v1/sims/{sim_id}/finalize` | — | `200 {scene_id, chapter_id, book_id, title, word_count, prose}` | 404 sim 不存在；400 无成文回合 |
| GET | `/api/v1/scenes/{scene_id}/prose` | — | `200 {scene_id, chapter_id, title, prose, word_count}` | 404 |
| GET | `/api/v1/chapters/{chapter_id}/prose` | — | `200 {chapter_id, book_id, title, order_no, word_count, scenes:[{scene_id,title,prose,finalized}], prose}` | 404 |
| GET | `/api/v1/books/{book_id}/export` | — | `200 text/markdown`，`Content-Disposition: attachment; filename="{书名}.md"`（UTF-8 filename* 编码） | 404 书不存在；400 无已定稿内容 |

约定：
- `word_count` = `len(prose)`（中文字符计数，与成文 180-280 字/回合口径一致）
- `finalized` = `final_prose` 非空
- finalize 不强制 converged（作者存稿自由，任何时点可定稿当前进度）；幂等覆盖

## 5. 决策与假设

1. **手动定稿**（用户拍板）：收束后按钮触发，非自动钩子——定稿权在作者
2. **场景维度落库、章节查询时聚合**：单点写避免双写不一致；章节无冗余列
3. **幂等覆盖**：重复 finalize / rewind 后重演再 finalize 均覆盖旧正文
4. **导出仅 markdown**：md 是作者生态通用格式；txt/epub 不在本次范围
5. **内存态修复 get_scene 属必要前置**：否则 pytest（内存态）无法断言落库结果
6. 沿用现有 DI 模式与 `_flatten_state` 扁平化风格，不引入新分层
