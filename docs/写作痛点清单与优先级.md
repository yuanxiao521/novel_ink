### S4 · 涌现式嵌入（亮点 · 分层+桥接）

> 定位：这不是"痛点改正"，而是**主动做的差异化亮点**。涌现式从绑定网文正文中解耦，作为独立的剧本产物 + 网文的上游高光源。

- **一句话**：把"涌现"和"网文"两种产物分层——涌现供料（产高光/转折/对话火花）、网文成书（把料稳住地写）。涌现式不再强行转网文正文，而是独立剧本产物，可选桥接喂给写手。
- **背景 / 初衷**：最初想用导演台回合驱动网文正文，发现二者矛盾（网文需强叙述/作者掌控，涌现是强互动/剧本味）。涌现式对强叙述网文不合适，但对**剧本/对话/角色碰撞**是天然优势，宜作为亮点，而非被网文正文"洗掉味道"。
- **三幕定位**：涌现式 = 三幕里的"高光发生器"，网文 = "把高光写成正文的底座"。分层关系，非替代。
- **现状**：**暂缓/未落地**。导演台"场景涌现"暂缓中；simulation 回合流 + 角色 think/act 已具备作为剧本产物的基础。
- **参考做法**：导演台回合调度 director.py / simulation.py、角色 think/act character.py（现有资产即可支撑剧本台）；STORYWRITER 事件图（高光提取思路）；Gonson 每章张力标注。
- **待办切入点**（分阶段）：
  - **step1 产物定型**：涌现式先产出**「回合事件流」为成品**（simulation 回合快照 + think/act 流本身即对话体/剧本体），**不再转译成叙述正文**，直接当剧本/对话记录导出。前端导演台保留"看角色自发互动"→ = 剧本创作台，不是正文生成台。
  - **step2 桥接（可选但妙）**：涌现跑出「事件核 / 对话高光 / 转折」，落成一个结构（事件表/hits），写手扩写时读它当素材。涌现变网文的**灵感发电机**，作者保留掌控（A 出料 → 作者挑 → B 扩写）。
  - 启发式触发点（重头戏才下钻涌现，其余走网文）：转折/高潮点、高冲突对话、收尾抉择；常规段仍走网文管线。
- **关联文档目标路径**：`写作优化方案-S4涌现式嵌入.md`

### S1 · 世界状态漂移

- **一句话**：战力 / 金钱 / 道具链 / 时间线 / 关键数字前后不一致，每隔几章露一次馅。
- **典型症状**：主角第 10 章"凝气三层"，第 30 章一掌毁山，第 50 章又写"凝气三层波动"；"三天可达 A 城"，可世界观设飞舟要一个月。
- **根因**：状态没建成**账本**，生成时数值即兴编、编完不校验不比对。
- **现状**：✅ **已交付（v1.9）**。`world_states` 账本（迁移 0012）+ `verify_prose.state_deltas` 写入 + 写手/主笔感知注入已全通；方案见 `写作优化方案-S1世界状态.md`。
- **参考做法**：InKOS 7 真相文件（character_matrix / particle_ledger / time anchors）；Gonson 跨章四表（道具链/时间锚/术语/关键数字）。
- **待办切入点**：角色状态卡(L2) → L3 append-only 状态流 → 四表扩展。
- **关联文档目标路径**：`写作优化方案-S1世界状态.md`

### S2 · 人物口吻漂移

- **一句话**：冷面剑客和话痨小贩，几章后变成同一个"AI 统一音色"。
- **典型症状**：开头多角色两个腔，读到第 5 章全是"嗯，确实""我明白了"；个性被抹平。
- **根因**：角色卡虽注入写手，但"腔调"约束被正文惯性冲淡，且**无口吻一致性校验回环**抓跑偏。
- **现状**：**部分（2026-09-13 实测更正）**。写手本应读角色卡，但字段名错位（`personality`/`tone`/`bottom_line` vs 真实的 `summary`/`traits`/`voice`/`bottom_lines`）→ 实际渲染成“（无详细设定）”，**等于没注入**（B16 已修），且仍无运行时校验"这句像不像这个角色说的"。
- **参考做法**：iCliniq character persona / roleplay think-act 分离（本项目 character.py 已做 think/act 分离，可复用思路到写手）。
- **待办切入点**：加角色状态卡(L2)进写手 prompt；体检/质检增"口吻一致性"校验维度。
- **关联文档目标路径**：`写作优化方案-S2角色口吻.md`

### S3 · 全局结构 / 张力失衡

- **一句话**：每章局部有冲突、写得热闹，全书却一马平川，没有起承转合 / 张力网络 / 伏笔呼应。
- **典型症状**：读者反馈"情节挺好但太平了"；伏笔各埋各的互不呼应，越写越散。
- **根因**：写手只见眼前一场景，缺一个看得见全书节奏 / 张力 / 结构的**全局视角**。
- **现状**：**未涉及**。导演台"场景涌现"暂缓，全局张力视角是真正空白。
- **参考做法**：tension-assessment skill；STORYWRITER 事件图大纲；Gonson 每章张力标注。
- **待办切入点**：**独立于导演台涌现**，先做轻量"全局张力/结构快照"（如按章节标注张力值、伏笔网络图），再谈自动化调度。
- **关联文档目标路径**：`写作优化方案-S3全局结构.md`

### A1 · 上下文遗忘

- **一句话**：内容多了以后，主角捡的剑、前文的断臂，写着写着就忘了/用错。
- **典型症状**：第 1 章废墟捡锈剑，第 20 章随手掏出没设定过的"天阶神兵"；前文断臂、后文双手齐上。
- **根因**：上下文窗口有限/超窗截断，记忆没外部化，全靠"这次对话还记得多少"。
- **现状**：**部分**。`book_memories` + 场景结构表兜底，小体量够用；但按 topic+最近 N 条枚举，无语义召回。
- **参考做法**：RAG 语义召回（触发后才接）；InKOS Mimir 记忆；STORYWRITER ReIO。
- **待办切入点**：体量小时靠结构化查询顶住；**正文量变大 → 激活 RAG**（此时接用户自带的 RAG 源码）。
- **触发条件**：正文量大 / 上百场景 / 记忆按枚举不够用时。
- **关联文档目标路径**：`写作优化方案-A1上下文记忆.md`

### A2 · 质量不稳定

- **一句话**：同配置下，这章惊艳、下章注水；温度一抖重大情节就崩，且查不到出在哪一步。
- **典型症状**：一次性成稿，写坏了既不自知也没人拦。
- **根因**：**单次生成、一次成稿**，无自评/回环/质量门槛过滤不合格版本。
- **现状**：**未涉及**。有 `schema_retry` 兜**结构**，无**内容级自评**。
- **参考做法**：NovelForge Writer⇔Editor 多轮；Gonson 每场景两轮独立 review。
- **待办切入点**：轻量自评（初稿后独立打分 → 低于阈值自动重写 1 次）。
- **关联文档目标路径**：`写作优化方案-A2质量回环.md`

### A3 · AI 腔同质

- **一句话**：满屏"深吸一口气""眼中闪过一丝…"，每段结尾升华，破折号狂飙；全角色共用一把 AI 音色。
- **典型症状**：读者一眼看出是 AI 写的。
- **根因**：模型统计倾向；光靠 prompt"别写 AI 腔"无效，需**确定性正则拦截**（了/是/的密度、套话词表、破折号计数）+ 定点重写。
- **现状**：**部分**。`skeleton-to-prose` / story-craft 已内化反 AI 味理念，但**无确定性校验器**落地。
- **参考做法**：InKOS 11 条确定性规则 + spot-fix；long-novel-agent 高频词审计。
- **待办切入点**：把反 AI 味升级成**可编程校验器**，接 `schema_retry.py` 纠错通道。
- **关联文档目标路径**：`写作优化方案-A3反AI味校验.md`

### A4 · 作者失控 / 一次性交付

- **一句话**：点一下生成涌出 3 章 / 8000 字，作者一半不满意却不知从哪改。
- **典型症状**：想微调一句要整篇重来；主笔整篇规划一次性交付，无节奏掌控。
- **根因**：生成粒度大、无分批+确认；缺过程掌控。
- **现状**：**部分**。场景级部分修改 + 正文协作已做 ✅；主笔整体规划仍一次性交付。
- **参考做法**：Novel-studio 分批写作 + 总编汇报 + 作者确认；NovelForge 断点恢复。
- **待办切入点**：主笔改分批交付（每批 N 章 → 汇报 → 确认 → 再下批）。
- **关联文档目标路径**：`写作优化方案-A4工作流门控.md`

### B1 · 伏笔断裂

- **一句话**：埋的坑忘了收，或回收时设定对不上。
- **根因**：无账本记录"埋了哪些 / 何时该收"。
- **现状**：**已缓解 ✅**。`foreshadows` 三位状态 + 收束章节 + 记账 Agent，对标 InKOS pending_hooks。
- **参考做法**：InKOS pending_hooks；Gonson 钩子台账。
- **待办切入点**：作为**亮点深化**（如增加"埋期超时自动提醒"、伏笔网络图、回收校验因果）。
- **关联文档目标路径**：`写作优化方案-B1伏笔深化.md`

## 4. 推进规则（防止一次性做太多）

1. 按等级顺序推进，**一次只展开一条**的独立方案文档（如 `写作优化方案-S1世界状态.md`）。
2. 每条方案写清：现状定位 → 目标 → 数据结构落点（表/字段）→ 改动文件 → 验收 → 触发条件。
3. 定级可随实测调整，更新本文件并把变化记入 `代码导航与Bug追踪Wiki.md` 的版本历史。
