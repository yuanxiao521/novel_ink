# 主笔 Agent 升级设计

> 版本 v0.3 · 2026-09-02（v0.2 基础上：需求对齐 · 对话隔离 · 写手上下文升级 · 正文协作独立路由）
> 依赖：`docs/MVP设计.md`（北极星/铁律）、`docs/prompt核心设定.md`（四层 prompt 分层）、`docs/agent职责与prompt设计.md`（四席职责表·S2 主笔）
> 定位：主笔从「预写的一次性函数」升级为「有感知/记忆/部分修改/纠错循环/元技能的创作 Agent」。与导演台职责解耦，正文走向「主笔生成 ↔ 作者手写」协作模式。

***

## 1. 背景与问题

现状主笔是**一组被前端按钮触发的预写函数**（见 `engine/chief_planner.py`）：

| 现状                                                             | 缺陷                           |
| -------------------------------------------------------------- | ---------------------------- |
| `plan_skelly(direction, context, inspirations)` 一次性 LLM 输出整本骨架 | 无感知：不读已有骨架现状，只能从零重排          |
| `chief_chat_stream` 每轮全量发 messages + 现读书树                      | 无记忆：对话框不按书持久化，多本书共用同一上下文（串味） |
| `commit_book_plan` 全量替换（前一版本用标题去重则堆积重复）                        | 无法部分修改：改一章一场景都要整本重排          |
| LLM 输出无校验重试                                                    | 无纠错：产出非法 JSON/结构直接抛错或落库脏数据   |
| 无元技能产出                                                         | 写作约束无法沉淀复用，无法约束将来其他 agent    |

另：导演台「场景涌现」对网文效果不理想，**暂缓**；正文改走「主笔生成初稿 ↔ 作者手写」协作，导演台保留（后续再探讨升级）。

## 2. 设计目标与边界

一句话：**主笔管内容决策，记账 Agent 管状态一致，导演台管场景演出（暂缓）。**

### 2.1 主笔职责（升级后）

| 域        | 能力           | 说明                                                                    |
| -------- | ------------ | --------------------------------------------------------------------- |
| ① 结构域    | 骨架/章节/场景增删改  | 最小粒度：**场景级全量**（章节内场景逐条增删改）                                            |
| ② 内容域    | 场景描述 + 正文生成  | 场景补「内容描述」（事件梗概/冲突点/环境细节）；正文提供「主笔生成初稿 ↔ 作者手写」双入口，落 `scene.final_prose` |
| ③ 记忆域    | 书级独立记忆       | 每本书独立记忆上下文（方向/已定设定/写作约束/修改历史/作者偏好）                                    |
| ④ 元技能域   | 产出写作约束/规则/模板 | 约束先存书级数据（参与感知），可一键导出 SKILL.md（走 skill-creator）供未来 agent 复用            |
| ⑤ 纠错循环   | 输出校验 + 重试    | LLM 产出 schema 非法 → 校验失败 → 重试 → 才落库                                    |
| ⑥ 感知（前置） | 行动前装配上下文     | 读「当前书树 + 书级记忆 + 已采纳灵感卡」再行动                                            |

### 2.2 不归主笔管（铁律）

- **回合级事实记账**（伏笔/信念/因果一致）：新增**记账 Agent**，正文保存后触发，自动维护

- **导演台回合涌现/收束分析**：暂缓保留，不并入主笔

- **裸 SQL / 直接文件系统写**：落库统一走 service→repo→ORM；产出约束以数据落库，不裸写 SKILL.md

## 3. 总体架构

```
作者（一句话方向 / 修改意见）
   │ 对话（书级记忆，分书隔离）
   ▼
┌─ 主笔 Agent（内容架构师 + 技能制定者）──────────────┐
│  感知：书树 + 书级记忆 + 已采纳灵感卡                 │
│  执行：骨架/场景部分修改 · 场景内容 · 正文生成         │
│  纠错：schema 校验 → 重试循环 → 才落库                │
│  元技能：写作约束/规则/模板 → 书级数据 → 可导出 skill │
└──────────────┬──────────────────────────────────┘
               │ ORM 落库（service → repo）
               ▼
     ┌──────────────── 世界层 ────────────────┐
     │ 书 / 章 / 场景 / 正文 / 伏笔 / 信念 / 因果 │
     └───────┬─────────────────────┬──────────┘
             │                     │
   ┌─────────▼────────┐   ┌────────▼─────────┐
   │ 记账 Agent（新增） │   │ 导演台（暂缓/保留）   │
   │ 保存正文后触发：    │   │ 回合涌现先不做，      │
   │ 更新伏笔/信念/因果  │   │ 后续再探讨升级        │
   └──────────────────┘   └──────────────────┘
```

## 4. 能力模块设计

### 4.1 记忆域（书级独立记忆）

新增 `book_memories`（书级记忆）落库，按 `book_id` 隔离：

```sql
-- book_memories（书级记忆上下文）
id          TEXT PRIMARY KEY
book_id     TEXT NOT NULL           -- 记忆属于哪本书（多书隔离关键）
topic       TEXT NOT NULL           -- 记忆主题：direction|setting|constraint|history|preference
content     TEXT NOT NULL           -- 记忆内容（LLM 提炼后的短文）
source      TEXT DEFAULT 'chief'    -- 来源：chief(主笔提炼)|author(作者声明)|audit(记账回写)
ts          BIGINT                  -- 时间戳（用于最近 N 条筛选）
```

- 主笔每次行动前按「topic + 最近 N 条」装配到 prompt

- 写作约束（元技能产出）也落到 `topic=constraint`，感知强制注入

### 4.2 感知域（行动前置）

`chief_perceive(book_id)`：读取 书树摘要 + 记忆前 N 条 + 已采纳灵感卡 + 伏笔现状 → 拼装上下文注入。所有主笔入口（规划/对话/正文生成/修改）统一走此函数，杜绝「从零重排」。

### 4.3 部分修改（场景级全量）

替代 `commit_book_plan` 的全量替换，新增场景级操作（前后端同步）：

- 章节：新增/删除/重命名/重排（已有 CRUD 保留）

- 场景：**增/删/改/重排**（标题、stage\_desc、goal、initial\_facts、cast、内容描述）

- 场景级全量：`PUT /books/{id}/chapters/{cid}` 用「场景列表整体替换」语义（传入完整场景数组，服务端 diff 后增删改），前端骨架树内联编辑后整体保存

- 落库仍走 ORM；骨架编辑不再触发整本重排

### 4.4 纠错循环

对 LLM 结构化输出统一做 `validate_and_retry`：

1. schema 校验（缺失关键字段/类型错 → 失败）
2. 失败 → 带错误信息重试（≤2 次，换措辞重新生成）
3. 仍失败 → 抛 422，**不落库**
   适用：plan 骨架 / 规则解析 / 正文生成 / 记忆提炼。

### 4.5 元技能域（约束资产两层）

- **第一层（书级数据）**：主笔产出的写作约束/规则/风格要求 → `book_memories(topic=constraint)` 或扩展 `books` 字段，参与主笔感知

- **第二层（导出 skill）**：提供「一键导出 SKILL.md」入口，把书级约束包装成可复用 skill（**走 skill-creator 流程**，非 LLM 裸写文件）

### 4.6 正文协作 · 工作区（v0.3 · 独立路由 + 写手上下文升级）

**形态**：独立路由页面 `/studio/:sceneId`，全屏专注写作。从 MaestroPage 场景列表的「正文协作」按钮跳转进入。场景保留但不完全绑定——正文可独立存在，未来按需搬入导演台演绎。

**写手上下文升级**（v0.3 关键改动）：

写手 prompt 从只注入场景 4 字段 → 升级为三层注入：

| 层     | 内容                                         | 来源                      |
| ----- | ------------------------------------------ | ----------------------- |
| ① 场景层 | title / stage\_desc / goal / content\_desc | scene 表                 |
| 角色层   | 本场出场角色的性格/腔调/底线/决策偏好                       | characters 表（按 cast 过滤） |
| ③ 前文层 | 上一场景 final\_prose 前 200 字摘要                | 同章节前一场景的 final\_prose   |

**四角色能力**（各自独立按钮调用）：

| 角色              | 输入                     | 输出                       | 校验（复用 validate\_and\_retry） |
| --------------- | ---------------------- | ------------------------ | --------------------------- |
| ✍ 写手 writer     | 场景 + 角色卡 + 前文摘要 + 书级记忆 | 正文初稿（流式）                 | 篇幅下限 + 非空                   |
| 🩺 体检员 editor   | 正文 + 场景上下文             | 体检报告：结构/逻辑/节奏/人设问题清单     | 报告项齐全（issue 数组非空可空报告）       |
| 🎨 润色师 polisher | 正文（写手稿或作者稿）            | 润色稿 + 改动摘要（**只改写法不动剧情**） | 与原文仅措辞差异校验（软）               |
| 🔍 质检员 verifier | 正文 + 伏笔/信念账本           | 质检意见：伏笔命中/推进建议/信念变化/因果补记 | 结构化意见合法 → **存 pending**     |

**审计记录** **`prose_notes`（迁移 0009 · 可追溯核心）**：

```sql
id / scene_id / kind(editor|polisher|verifier|writer)
status(pending → approved|rejected)
suggestion TEXT    -- 问题/建议/改动摘要
before TEXT        -- 改动前正文（润色/体检引用）
after  TEXT        -- 改动后正文（润色产出）
created_by TEXT    -- writer|editor|polisher|verifier
reviewed_at / ts   -- 作者审阅时间线
```

- 每步体检/润色/质检写一条记录（pending）；作者 approve/reject 后才生效

- 落库行为（final\_prose / 伏笔推进 / 信念 / 因果）全部关联记录 → 可回查"这条设定是哪次质检、谁同意的"

**工作流**（独立路由页面内）：

```
├─ ✍ 写手生成初稿 ─────────────→ 正文编辑区（流式）
├─ 🩺 体检员体检 ──┬── 与质检并行 ─→ 报告卡 ↓ 作者过目
├─ 🎨 润色师润色 ──┘               → 润色稿 diff 预览 → [应用]（写一条 polisher note）
├─ 🔍 质检员质检 ─────────────→ 意见清单 → 作者勾选 → [✅ 确认入账]
└─ 💾 保存正文（final_prose 落库，幂等 hash 判重）
```

- 质检 = 阶段⑤记账的**前置环节**：意见先落 pending，作者确认后才写伏笔/信念/因果账本

- 写手/润色复用 `skeleton-to-prose` 的反 AI 味写作规则 → 独立「润色 skill」（走 skill-creator）

### 4.7 记账 Agent（保存正文后触发）

独立流程，非常驻服务：

1. **触发**：正文 `final_prose` 保存成功后
2. **读**：该场景正文 + 场景描述 + 伏笔现状 + 角色信念现状
3. **写**（LLM 结构化输出，落库）：

   - `foreshadows`：状态推进（buried → in\_progress → closed）、补充新伏笔

   - `beliefs`：角色认知变化（perceived/told/inferred）

   - 因果补记（事件 caused\_by/causal\_pressure，若该场景无 sim 事件则跳过）
4. 幂等：同一场景同一版本正文只记一次（用 final\_prose 内容 hash 判重）

## 7. v0.3 需求对齐（2026-09-02 实测后结论）

### 7.1 已确认问题

| # | 问题                          | 根因                                                                  |
| - | --------------------------- | ------------------------------------------------------------------- |
| 1 | 主笔共创对话历史所有书共用，切换书不清空        | 前端 `messages` 是组件级单一 state，初始化为硬编码 `INIT_MESSAGES`，切换 `bookId` 时不重置 |
| 2 | 写手生成正文"随意"，跟角色/前文无关         | 写手 prompt 只注入场景 4 字段（title/stage/goal/content\_desc），无角色卡、无前文、无伏笔   |
| 3 | 体检/润色/质检流程不清晰，作者不知道每个角色做了什么 | 四个角色是平行按钮，无工作流感；输出展示不够直观                                            |
| 4 | 正文协作入口是场景列表里的小按钮弹窗，体验割裂     | 弹窗模式不适合专注写作；场景列表入口太隐蔽                                               |

### 7.2 对齐结论

| 决策项         | 结论                                                                     |
| ----------- | ---------------------------------------------------------------------- |
| **对话历史**    | 按书隔离 + 持久化。后端存 `chat_histories` 表（book\_id 隔离），前端切换书时加载该书历史，新建书从空白开始   |
| **写手上下文**   | 注入：场景设定 + 出场角色卡（性格/腔调/底线）+ 上一场景 final\_prose 摘要。让写手知道"谁在演、怎么演、前面发生了什么" |
| **正文协作入口**  | 改为独立路由页面 `/studio/:sceneId`，全屏专注写作。场景列表的"正文协作"按钮改为跳转路由                 |
| **正文与场景关系** | 场景保留但不完全绑定。正文可独立存在，未来按需搬入导演台演绎                                         |

### 7.3 新增/调整实施项

| 阶段         | 内容                                       | 说明                                                                       |
| ---------- | ---------------------------------------- | ------------------------------------------------------------------------ |
| ⑧ 对话持久化    | `chat_histories` 表 + 前端按书加载/保存           | 替代前端内存态 messages，切换书时后端返回该书历史                                            |
| ⑨ 写手上下文升级  | `draft_prose` prompt 注入角色卡 + 前文摘要        | 后端新增 `get_scene_characters(scene_id)` + `get_prev_scene_prose(scene_id)` |
