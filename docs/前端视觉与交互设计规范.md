# 涌现式小说 Agent · 前端视觉与交互设计规范

> 版本 v0.1 · 2026-08-24
> 定位：前端视觉系统的设计总纲，覆盖 MVP 范围并预留扩展。与 `MVP设计.md` 配套使用——后者定产品逻辑，本文件定视觉与交互语言。
>
> **核心原则**：界面要让用户**看见世界在长出来**，而不只是看结果。整体气质是「舞台导播台」——信息密度高、能看戏、有幕后操控感。

---

## 1. 视觉设计方向 / Moodboard

### 1.1 整体气质：舞台导播台 + 手稿纸感

**核心隐喻**：作者=剧场导演，坐在导播间里，面前是多块监视器，实时观看舞台上角色的自主表演。导演可以通过控制台"举手"介入，但只给方向、不给台词。

- **骨架气质**：导播监控台——深色底、多面板、信息密度高、有"幕后感"
- **肌肤质感**：手稿/剧本纸——文字区域有纸本温度、排版有文学气息
- **动态意象**：涌现——信息从"模糊颗粒"逐渐"凝结成字"，角色行动像水面涟漪扩散

**不是什么**（明确划界）：
- ❌ 不是游戏 HUD——不要血条/技能条/数值爆闪
- ❌ 不是数据仪表盘——不要纯图表堆砌、不要为了可视化而可视化
- ❌ 不是科幻赛博朋克——不要霓虹光条、不要全息投影感

### 1.2 色板建议

#### 基础中性色（导播台底色）

| 层级 | 暗色值 | 亮色值 | 用途 |
|------|--------|--------|------|
| 最深底 | `#0D0F14` | `#F7F5F0` | 页面底色、沉浸模式背景 |
| 面板底 | `#151922` | `#FFFFFF` | 卡片/面板背景 |
| 分隔线 | `#232836` | `#E8E4DC` | 边框、分隔线 |
| 次强调 | `#3A4157` | `#B8B0A0` | 次要文字、禁用态 |
| 正文 | `#C9CDD6` | `#2A2824` | 主文本 |
| 高亮 | `#EDEFF2` | `#1A1815` | 标题、强调文本 |

#### 功能色（导播台信号灯）

| 功能 | 颜色 | 语义 |
|------|------|------|
| 导演金 | `#E8B860` | 导演举手、介入操作、主 CTA |
| 张力红 | `#D96A6A` | 冲突/张力、护栏告警、OOC 标记 |
| 涌现青 | `#6AB5C9` | 角色行动、事件流入、新信息出现 |
| 共识绿 | `#7CB87C` | 护栏通过、收束达成、状态正常 |
| 信息蓝 | `#7C9CD4` | 系统消息、环境事件、元信息 |

#### 场景级情绪色板（详见 §3）

每个 mood 有独立的"氛围色"，作用于背景渐变、卡片描边、强调色——只换皮肤、不动布局。

### 1.3 字体与排版气质

**字体选择**：
- **标题/界面文字**：无衬线字体（系统 `sans-serif` 栈）——干净、冷静、导播台感
- **小说正文**：衬线字体（系统 `serif` 栈 + 宋体后备）——文学感、纸本质感
- **代码/事件 ID**：等宽字体（`monospace`）——技术感、日志感

**排版节奏**：
- 作者工作台：紧凑行高（1.4–1.5）、小字号（13–14px）、信息密度优先
- 阅读台沉浸模式：宽松行高（1.8–2.0）、大字号（16–18px）、阅读舒适度优先
- 事件日志：等宽字体、行高 1.5、时间戳左对齐固定宽度

**关键排版细节**：
- 角色对话用**引号 + 角色名左标签**呈现，不做聊天气泡（避免 IM 感）
- 内心独白用**斜体 + 低透明度**呈现，与对话区分
- 环境叙述用**正文样式 + 首行缩进**呈现

### 1.4 关键视觉隐喻

| 隐喻 | 视觉表现 | 对应产品概念 |
|------|----------|-------------|
| **导播台监视器** | 深色面板 + 细边框 + 顶部标题条 + 状态指示灯 | 各信息面板（角色、黑板、时间线） |
| **舞台聚光灯** | 中心区域略亮、边缘渐暗、微光晕 | 世界黑板主视图 / 成文预览 |
| **手稿纸** | 米白底 + 微妙纹理 + 衬线字体 | 沉浸阅读模式 |
| **涟漪扩散** | 新事件从中心向外渐显、波纹动效 | 事件写入黑板时的涌现感 |
| **信息差阴影** | 角色卡片上"已知/未知"用透明度差异表达 | 信念账本 / 感知标签 |
| **举手信号灯** | 导演金 + 脉冲呼吸动效 | 导演举手请求介入 |

### 2.2 左栏：角色侧栏（Characters Panel）

**MVP 功能**：2–3 个角色卡片，展示角色状态与信念账本。

**角色卡片结构**（每个角色一块）：

```
┌─────────────────────────┐
│ [头像]  陈默            │
│ 情绪：沉思 ───●──── 紧张│
│ 目标：查明真相 (权重 0.7)│
├─────────────────────────┤
│ 信念账本  已知 12 条     │
│  ─ 李文深夜出门（亲见）  │
│  ─ 保险柜被动过（推测）  │
│  ─ ... (展开更多)       │
└─────────────────────────┘
```

**关键设计点**：
- **头像**：像素风或二次元立绘缩略（32×32px），点击展开大图 + 情绪态切换
- **情绪条**：水平渐变色条（绿→黄→红），标注当前情绪在"平静–紧张"谱系上的位置，旁边用文字标签
- **目标权重**：用进度条样式展示，权重变化时伴随**微闪烁**提示（导演调整了权重）
- **信念账本**：
  - 每条信念显示「内容摘要 + 获知渠道标签」——`亲见`/`被告知`/`推测`
  - 标签颜色：亲见=涌现青、被告知=信息蓝、推测=次强调色
  - 悬停显示溯源信息："通过事件 E-042 获知"
  - "信息差"可视化：不同角色卡片的信念条目用**透明度**区分——当前选中角色"已知"的是实心，"未知"的是虚影（仅在"对比视角"模式下显示）

**角色间信息差对比**（MVP 轻量版）：
- 顶部有一个"视角切换"下拉：`全局视角` / `陈默视角` / `李文视角` / `周婶视角`
- 切换到单角色视角时，该角色卡片高亮，世界黑板中"该角色不可见的事实"变为灰色虚影——直观呈现"角色只看到局部世界"

**双标签切换**：「黑板视图」↔「成文视图」

#### 黑板视图（默认）

展示当前世界状态的结构化视图——这是"模拟层"的可视化。

```
│  • 窗外下着雨                                    │
│  • 桌上有一杯凉茶                                │
│  • 保险柜门半开（可见度：陈默✓ 李文✓ 周婶✗）     │
│                                                  │
│  【当前回合事件】                                 │
│  ┌──────────────────────────────────────────┐   │
│  │  李文：「默哥，这文件……你什么时候放的？」  │   │
│  │  （陈默感知 ✓  周婶感知 ✗）               │   │

│                                                  │
```

**关键设计点**：
- **场景标题条**：场景名 + 时间 + 天气，带小图标，营造舞台场景感
- **环境事实列表**：每条事实后面跟「可见度标签」——用角色名缩写的对号/叉号表示谁能感知到
- **当前回合事件**：高亮卡片，像舞台上的"正在发生"
- **角色状态摘要**：每角色一行，格式为`角色名：情绪标签 —— 状态描述`
- **涌现动效**：新事实/新事件出现时，从底部淡入+轻微上浮，像"从水面浮现"
- **护栏标记**：被护栏拦截的事件用红色描边 + 角标「护栏拦截」，点击可查看拦截原因

- **导演提示**：只读区域，展示导演每回合的软引导内容，用标签分类（舞台提示/感知曝光/目标权重）
- **介入工具**：三个主要按钮，点击展开对应表单

- **护栏状态**：底部状态栏，三层护栏的通过状态用图标表示，"本回合拦截次数"和"熔断计数"实时更新

### 2.5 底部：时间线 / 事件流（Timeline）

**MVP 功能**：横向时间线 + 回放控制 + 事件日志查看。

```
┌──────────────────────────────────────────────────────────────┐
│  ⏮  ◀  ▶  ⏭   ● 实时模式  ↻  速度: 1x    共 7 回合 / 23 事件  │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  T-01 ───── T-02 ───── T-03 ───── ● T-04 ───── T-05 ──→      │
│  场景初始化   初次对话    发现异常   🔴当前   李文试探         │

│  事件类型图例：[角色行动] [环境事件] [导演提示] [成文] [私感知] │
└──────────────────────────────────────────────────────────────┘
```

**关键设计点**：
- **回放控制**：跳到开头 / 上一回合 / 播放暂停 / 下一回合 / 跳到末尾 —— 标准播放器布局
- **实时/回放模式切换**：实时模式下时间线自动推进；回放模式下进入"查看历史"状态，面板显示历史快照
- **回合节点**：每个回合是一个节点，节点内显示回合摘要（一句话）
- **当前回合**：高亮圆点 + 脉冲动画
- **事件类型颜色编码**：
  - 角色行动 = 涌现青
  - 环境事件 = 信息蓝
  - 导演提示 = 导演金
  - 成文渲染 = 次强调色
  - 私感知 = 紫色（仅在全局视角可见）
- **点击回合节点**：主舞台区跳转到该回合的快照，所有面板同步切换到对应时间点的状态
- **速度控制**：0.5x / 1x / 2x / 4x —— 回放时可调速
- **日志详情**：双击回合节点或点击「查看日志」按钮，展开事件日志面板（等宽字体、JSON/结构化格式展示完整事件数据）

## 3. 主题系统设计

### 3.1 设计原则

1. **深浅双主题自动切换**：跟随系统偏好，也允许用户手动切换
2. **场景级换肤**：每个场景有 `mood` 字段，前端据此加载对应色板——只在场景切换时换肤，不做实时变色
3. **CSS 变量驱动**：所有主题色通过 CSS 自定义属性实现，切换主题只改变量值
4. **长时阅读友好**：对比度适中、不刺眼、低蓝光倾向

```css
  --accent-cyan: #3A8EA5;
  --accent-green: #4A8A4A;
  --accent-blue: #4A6DB0;
}
```

### 3.3 场景级 Mood 色板

场景 mood 作为**叠加层**，在基础主题之上修改"氛围色"变量，不影响功能色。

| Mood | 氛围主色 | 氛围次色 | 背景渐变 | 适用场景 |
|------|----------|----------|----------|----------|
| **悬疑** `suspense` | `#4A5B8A` 深靛蓝 | `#2A3A5C` | 从深靛蓝到黑的径向渐变 | 推理、未知、谜团 |
| **温情** `warmth` | `#C47B5A` 暖陶土 | `#8B5A3C` | 从暖橙到米白的柔光渐变 | 日常、情感、回忆 |
| **紧张** `tension` | `#8B3A3A` 暗红 | `#5C1A1A` | 从暗红到黑的收敛渐变 | 冲突、对峙、危机 |
| **宁静** `serene` | `#5A8A7B` 雾绿 | `#3A5A4C` | 从雾绿到深灰的柔和渐变 | 独处、自然、过渡 |

**实现方式**：

```css
/* mood 叠加在基础主题之上，只改氛围相关变量 */
[data-theme="dark"][data-mood="suspense"] {
  --mood-primary: #4A5B8A;
  --mood-secondary: #2A3A5C;
  --mood-bg-gradient: radial-gradient(ellipse at center, #1A2040 0%, #0D0F14 70%);
  --mood-border-glow: rgba(74, 91, 138, 0.3);
}

[data-theme="dark"][data-mood="tension"] {
  --mood-primary: #8B3A3A;
  --mood-secondary: #5C1A1A;
  --mood-bg-gradient: radial-gradient(ellipse at center, #3A1A1A 0%, #0D0F14 70%);
  --mood-border-glow: rgba(139, 58, 58, 0.3);
}
```

**Mood 影响的视觉元素**（有限范围，避免晃眼）：
- 页面背景的微妙渐变（`--mood-bg-gradient`）
- 面板激活态的描边光晕（`--mood-border-glow`）
- 场景标题的装饰色（`--mood-primary`）
- 张力曲线的填充色（mood 色 + 透明度）

**Mood 不影响的**：
- 功能色（导演金/张力红/涌现青等语义色保持不变）
- 文本对比度（确保 WCAG AA 以上）
- 布局结构

### 3.4 沉浸模式主题（读者阅读台）

沉浸模式是一套**独立的视觉配置**——低干扰、强氛围、全屏。

```css
[data-mode="immersive"][data-mood="suspense"] {
  --bg-page: #0A0D14;          /* 更深的底 */
  --text-primary: #B8BCC8;     /* 略暗的文字，不刺眼 */
  --reading-max-width: 680px;  /* 阅读列宽 */
  --reading-line-height: 2;    /* 宽松行高 */
  --ui-opacity: 0.3;           /* UI 元素默认半透明，hover 才浮现 */
}
```

**沉浸模式的交互**：
- 鼠标静止 3 秒后，所有 UI 元素（顶栏、页码、设置）淡出（opacity 降到 0.1）
- 移动鼠标或按任意键，UI 淡入
- 左右箭头翻页，空格下一回合
- 底部只有一个细细的进度条，表示当前阅读进度

## 4. 读者阅读台（沉浸模式）

### 4.1 定位

读者阅读台 = 纯粹的成文层展示，只看"小说"，不看"引擎"。

两种模式：
- **默认阅读模式**：有章节导航、目录、设置面板
- **沉浸模式**：全屏、低干扰、强氛围

### 4.2 布局结构

```
┌──────────────────────────────────────────────────┐
│  ← 返回   背叛之夜   第七章    ⚙ 设置   ☁ 分享   │
│  (hover 才显示)                                   │
├──────────────────────────────────────────────────┤
│                                                  │
│              第七章 雨夜的试探                     │
│                                                  │
│     窗外的雨越下越密，敲打着窗棂，像某种不安的     │
│  节拍。陈默坐在书桌后，目光落在那杯早已凉透的茶     │
│  上，却没有端起来的意思。                          │
│                                                  │
│     李文站在桌前，手指无意识地绞着衣角。沉默了     │
│  几秒，她终于开口：                                │
│                                                  │
│          "默哥，这文件……你什么时候放的？"          │
│                                                  │
│     陈默抬起眼，没有直接回答，只是缓缓问：         │
│                                                  │
│          "你怎么会问这个？"                        │
│                                                  │
│  ─────────────────────────────────────────────── │
│                                                  │
│  ◀ 上一章         7 / 23 回合         下一章 ▶    │
│  (hover 才显示)                        (hover)    │
└──────────────────────────────────────────────────┘
```

### 4.3 关键设计点

**排版**：
- 单列居中，最大宽度 680px（舒适阅读宽度）
- 衬线字体，行高 1.9–2.0
- 段落首行缩进 2 字符
- 章节标题居中，上下留白大（2–3 行高）
- 对话段落：缩进更多，或用引号+角色名标签区分

**氛围营造**：
- 背景是 mood 对应的渐变 + 极淡的纹理（纸纹或噪点）
- 文字区域有微妙的"聚光"效果——中心略亮，边缘渐暗（像舞台追光打在书页上）
- 场景切换时，有 1 秒的交叉淡入淡出（cross-fade），同时 mood 色板平滑过渡

**角色呈现**（轻量，不抢戏）：
- 对话段落左侧有角色头像缩略（16×16px，圆形）
- 头像会随情绪态变化（但只有几帧静态切换，不做动画）
- 悬停头像显示角色名 + 当前情绪标签

**沉浸模式的进入/退出**：
- 点击右下角"沉浸模式"按钮，或按 `F` 键
- 进入时：所有 UI 元素滑出/淡出，阅读区域放大
- 退出时：移动鼠标到屏幕顶部，UI 从顶部滑入

## 5. 角色情绪态与人物呈现

### 5.1 风格选择：像素风优先

**MVP 建议采用像素风**，理由：
- 实现成本低，几帧静态图即可表达情绪
- 与"导播台/复古监视器"气质契合
- 小巧、信息密度高，适合多面板布局
- 二次元立绘成本高，MVP 阶段不建议投入

**像素风规格**：
- 头像尺寸：32×32px（工作台侧栏）/ 64×64px（展开详情）
- 风格：16-bit 时代日式 RPG 像素头像（大眼、表情鲜明）
- 每个角色 4–6 个情绪态

### 5.2 情绪态谱系

MVP 只需 5 种基础情绪，覆盖大多数戏剧场景：

| 情绪态 | 像素表现 | 色板偏移 | 触发条件 |
|--------|----------|----------|----------|
| **平静** `calm` | 眉眼舒展、嘴角平直 | 中性 | 日常对话、过渡场景 |
| **思考** `thinking` | 眉微蹙、眼略眯、手托下巴 | 偏蓝 | 分析、推理、犹豫 |
| **紧张** `tense` | 眉紧皱、嘴角下压、出汗 | 偏红 | 冲突、对峙、被质疑 |
| **悲伤** `sad` | 眉下垂、眼角含泪、嘴角下撇 | 偏灰蓝 | 失落、回忆、共情 |
| **愤怒** `angry` | 眉倒立、眼瞪大、嘴紧抿 | 偏深红 | 爆发、指责、决裂 |

**扩展态**（第二阶段再加）：惊讶、喜悦、狡黠、恐惧、决绝……

### 5.3 情绪呈现机制

**三层表达**（由弱到强，避免信息过载）：

1. **微指示**（默认始终可见）
   - 角色卡片上的情绪文字标签 + 情绪条
   - 对话旁的头像（已带情绪态）

2. **中指示**（hover / 选中时显示）
   - 角色卡片展开，显示 64×64 像素立绘
   - 情绪变化原因：一行说明（"因李文的质问而警觉"）

3. **强指示**（情绪突变时短暂出现）
   - 情绪跳变超过阈值时，头像有一个 0.3 秒的"闪一下"效果
   - 伴随事件流中的情绪标记高亮

**禁忌**：
- ❌ 不做实时情感曲线每帧变色（违背硬约束）
- ❌ 不做面部动画、口型同步（MVP 不做动画演出）
- ❌ 不做全身立绘（成本高、占空间大）

### 5.4 信息差的视觉表达

这是产品核心概念——"角色只见局部"——必须在视觉上让作者**一眼看出谁知道什么**。

**信念账本的可视化**：

```
陈默的已知（12条）         李文的已知（9条）
━━━━━━━━━━━━━━━          ━━━━━━━━━━━━━
✓ 保险柜被动过            ✗ 保险柜被动过   ← 灰色虚影
✓ 李文深夜出门            ✓ 李文深夜出门
✓ 周婶是管家              ✓ 周婶是管家
✓ 文件被移动过            ✗ 文件被移动过   ← 灰色虚影
...                        ...
```

**全局视角下**：
- 所有事实都显示
- 每条事实后面跟「可见标签」——用角色头像小图标 + 对号/问号表示谁知道
- 角色视角切换时，"不知道"的事实变成 30% 透明度的虚影

**角色视角下**（模拟读者扮演模式的预览）：
- 该角色知道的事实 = 正常显示
- 该角色不知道的事实 = 完全隐藏（不是虚影，是真的看不到）
- 该角色"以为知道但其实错了"的 = 显示但带"⚠ 可能有误"标记（信念账本的可信度字段）

## 6. 设计语言说明（给前端开发者）

### 6.1 技术栈建议

- **框架**：React + TypeScript（与后端 FastAPI 配合，类型共享）
- **样式**：CSS Modules 或 Tailwind + CSS 变量（主题系统用原生 CSS 变量最方便）
- **状态管理**：Zustand（轻量，适合多面板共享状态）
- **事件流渲染**：虚拟滚动（事件日志可能很长）
- **动画**：CSS transitions + 少量 Framer Motion（场景切换、淡入淡出）

### 6.2 前端架构建议

**数据层**：
- 所有 UI 订阅同一个 `simulationState` store（世界状态 + 事件流 + 角色状态 + 导演状态）
- 通过 WebSocket 或轮询从后端获取状态更新
- 事件日志 append-only，前端增量追加

**视图层**（三视图共用同一数据层）：
- `AuthorWorkbench` — 作者工作台（三列 + 时间线）
- `ReaderView` — 读者阅读台（单列阅读）
- `RolePlayView` — 读者扮演台（backlog，预留路由）

**共享组件**：
- `CharacterCard` — 角色卡片
- `EventTimeline` — 时间线
- `BeliefLedger` — 信念账本
- `MoodProvider` — Mood 主题提供者
- `InterventionPanel` — 介入工具面板

### 6.3 主题切换实现方案

```
基础主题（light/dark）
    ↓ 叠加
场景 Mood（suspense/warmth/tension/serene）
    ↓ 叠加
视图模式（workbench/immersive）
```

三层叠加，全部通过 CSS 变量 + `data-*` 属性实现：

```html
<html data-theme="dark" data-mood="suspense" data-view="workbench">
```

切换只改属性值，CSS 自动应用对应变量。

### 6.4 关键交互规范

**介入操作的确认机制**：
- 注入事件 / 调权重 / 信息曝光——三种介入操作都需要二次确认
- 确认弹窗展示"预期影响"：影响哪些角色、可能改变什么
- 权重调整必须填写"剧情内因"，否则提交按钮禁用（v0.2 硬约束）

**举手的通知机制**：
- 导演举手时：顶栏金色脉冲 + 右栏介入面板高亮 + 轻微提示音（可选）
- 用户可以设置"自动暂停"——举手时自动暂停回合推进，等作者决策

**回放的状态隔离**：
- 进入回放模式时，所有面板显示历史快照，但不允许介入操作
- 回放模式下介入工具面板变灰，显示"回放中，不可介入"
- 退出回放回到"最新回合"

### 6.5 响应式策略

MVP 优先桌面端（作者工作台是重信息密度场景，不适合小屏），但做基础响应式：

- **≥1280px**：三列完整布局（标准桌面）
- **1024–1279px**：右栏导演控制台可折叠为图标条
- **768–1023px**：左右栏都可折叠，中央区为主
- **<768px**：只保留中央区 + 底部时间线，其他收入抽屉

读者阅读台的响应式更好做——单列布局天然适配各种屏幕宽度。

## 7. 补充交互细节（主动建议）

### 7.1 "涌现感"的微交互

**事件写入动效**：
- 新事件出现在时间线上时，从一个小点"扩散"成事件卡片——像水滴落入水面的涟漪
- 世界黑板上新事实出现时，从底部淡入上浮 4px，持续 0.4 秒
- 角色信念账本新增条目时，条目左侧有一个短暂的"涌现青"高亮条，2 秒后消退

**回合推进的节奏感**：
- 回合切换时，中央舞台区有一个极短的"闪黑"（0.15 秒 opacity 降到 0.7 再恢复）——像戏剧中的"暗转"
- 时间线上的当前回合节点有轻微的脉冲呼吸

### 7.2 护栏拦截的可视化

- 被护栏拦截的事件在时间线上是"空心 + 红色描边"的节点
- 点击被拦截事件，显示拦截详情：哪层护栏拦截的、拦截原因、打回了几次、是否熔断
- 熔断事件（打回 2 次仍不过，降级放行）有特殊标记「⚠ 瑕疵」，供作者事后审查

### 7.3 收束达成的仪式感

- 当剧情收敛到结局状态时，中央舞台区出现"收束卡片"
- 卡片展示：结局类型（背叛暴露/隐瞒成功/关系修复/公开决裂）+ 达成回合数 + 关键路径摘要
- 背景有轻微的"聚光收束"动效——光从四散收缩到中心，像戏剧落幕

### 7.4 事件日志的调试视图

给开发者/调优者用的"调试模式"（可在设置中开启）：
- 事件日志展开为完整的 JSON 视图
- 显示每个事件的 token 消耗、护栏检查耗时、模型调用信息
- 显示角色决策的"内部独白"（角色 Agent 的推理过程，正常模式下不展示）

## 8. 三视图关系总结

| 视图 | 用户 | 信息范围 | 视觉基调 | 核心动作 |
|------|------|----------|----------|----------|
| **作者工作台** | 作者/导演 | 全局（全知视角） | 导播台·深色·高密度 | 观察、介入、回放 |
| **读者阅读台** | 读者 | 成文层（只看小说） | 纸本·浅色/沉浸·氛围 | 阅读、翻页 |
| **读者扮演台** | 读者（远期） | 局部（角色感知范围） | 受限视野·信息不对称 | 说话、行动、观察 |

**统一性**：三者共用同一套色彩系统、同一套角色视觉语言、同一个数据底座。
**区分度**：通过布局密度、信息透明度、交互方式来区分场景——作者"操控一切"，读者"沉浸其中"，扮演者"只见局部"。
