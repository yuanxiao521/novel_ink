# Prompt 核心设定（角色 agent 感知/决策/演绎规范）

> Status: ALIGNED（基调共识稿）
> Author: 作者（YuanXiao）
> Last updated: 2026-08-25
> 用途：**规范未来开发流程的基调文档**。任何涉及角色 prompt、环境感知、导演/编辑 prompt、skill 挂载的开发，先对照本文档，不得跑偏。

## Why

角色 Agent 要"自主感知、决策、执行、自我演绎"，其 LLM Prompt 不能是一坨写死的话术。作者明确设计：**同一份"世界"，按层裁剪后喂给不同 agent**——不能让一个角色卡塞下全世界，也不能让导演看不见全局。此文档定 Prompt 的分层基调，约束角色卡／世界／导演三者的 prompt 边界，指导未来开发（角色演绎 skill、导演调度 skill、一致性校验 skill、前端人物页编辑）。

## 核心原则：Prompt 分层 ＝ 数据分层

Prompt 不是另起一套话术，而是**同一份世界数据，按层裁剪后注入不同的 agent**。谁读到什么，由运行时数据可见性决定，Prompt 只负责"怎么演/怎么想"。

| 层 | 归属 | 可编辑性 | 注入给 | 内容 |
|---|---|---|---|---|
| ① 书籍层 | 顶层 · 全书共享 | 作者改（未来） | 导演/编辑/审计/体检层 + skill | 世界背景／世界观、人物关系网、全书统一写作规矩 |
| ② 导演/编辑/审计层 | 全局视角 | 作者介入（举手） | 导演 skill／编辑 skill／审计体检 skill | 读顶层 + 全量黑板 + 信念账本全貌 → 出软引导／张力评估／举手／收束／一致性体检 |
| ③ 环境感知层 | 场景级 · 动态 | 不可直接编辑（运行时生成） | 所有角色（按 `visible_to` 裁剪） | 当前事实／环境／可见子集 → 信息差来源 |
| ④ 角色卡层 | 私有 · 每个角色一份 | 作者通过前端"人物页"改 | 该角色 | 性格／腔调／底线／决策偏好 + 自己知道的 + 自己那份信念账本 |

## 分层职责（互不越界）

- **① 书籍层**：全书共享设定，**不常变**，按需注入给 ② 及 ② 挂的 skill。不塞进角色卡。
- **② 导演/编辑/审计层**：读全局（顶层设定 + 世界黑板 + 信念账本全貌），**只给方向、不代写台词**（铁律 #1 涌现优先）。出三把巧劲（注入事件/曝光信息/调权重，MVP §6.1）+ 举手 + 收束判定 + 一致性体检。未来挂 skill：导演调度／张力场判定／一致性审校。
- **③ 环境感知层**：由 `WorldState`（facts / envConds / visible_to）动态生成，按角色裁剪，是信息差与涌现的空间来源。此层**不是**作者编辑的静态话术。

> **场景层 ≠ 环境层（术语钉死）**：一个章节/场景分两半——
> - **章节/场景 = 静态"框"**：是谁的舞台布置（场景 ID、静态道具、开场氛围），偏顶层/章节实体，作者/导演可编辑，不随回合变。
> - **③ 环境感知层 = 框里的"动态现场"**：这一场戏目前进行到哪（柜门当前半开/已锁、此刻谁在、谁看见了什么），由 `WorldState.facts` 每回合刷新，运行时生成，不可直接静态编辑。
> - 角色做③感知时读到的是**动态现场**，不是章节的静态布置；两者分开存，避免"作者改场景=改文案"与"状态实际在变"互相打架。

- **④ 角色卡层**：私有 prompt，每角色一份，前端"人物页"可改（性格特点、演绎偏好）。只感知**自己的子集**（自己的 beliefs + ③ 过滤后的环境），**不读全量黑板**。

## 最终注入给一只角色的 LLM Prompt

```
③ 环境感知（visible_to 裁剪后的场景动态现场）
+ ④ 角色卡（性格/腔调/底线/决策偏好）
+ ② 导演引导暴露（被曝光则 + 相关信念/权重带剧情内因）
```

三者拼装后，角色才据此"感知 → 决策（内含思考/理由）→ 行动 → 记忆（信念账本回流）"。

## Skill 挂载位置

- 顶层/导演层 skill（导演调度、张力场判定、一致性审校、审计体检）在 **② 层**被调度。
- 角色演绎 skill、角色卡生成器在 **④ 层**被调度。
- skill 只封存"怎么演/怎么想/怎么审"的流程与准则，不含一次性任务数据（对齐 MVP §12.3）。

## Assumptions

- 角色卡本身需要通过 prompt 注入 → 因此角色卡的"演绎 prompt 模块"字段是必要能力，且**前端可改**（作者改性格/演绎偏好，属④层）。
- "环境感知"是**场景动态**，由代码运行时生成，不是作者静态编辑的话术。
- 世界/人物关系 = 顶层共享，"按需注入"给导演/编辑/审计，同时也沉淀为将来 skill 的世界观参照。

## 可接受的验证口径（AC）

- AC-1（分层清）一份世界数据，能按 ①顶层 ③环境 ④私有 三种粒度各自裁剪，互不混写。
- AC-2（角色私有）角色注入的 prompt 只含自己的信念账本子集 + visible_to 环境子集，不含全量黑板。
- AC-3（顶层注入）导演/编辑/审计层能读到顶层世界与人物关系设定（将来 Book 层就位后天然满足；本次以现 `WorldState.settings` 承载）。
- AC-4（可编辑）角色卡的演绎 prompt 模块（性格/腔调/底线/决策偏好）能被作者改（数据模型可写即可，UI 实现另算）。
- AC-5（不越界）导演管方向、角色管演绎：导演 prompt 不产出角色台词（MVP 铁律 #1）。

## Edge cases & risks

| 类别 | 说明 |
|---|---|
| 信息差被破坏 | 若 ③ 环境层不小心把全量事实注入给角色，涌现消失；靠 `visible_to` 硬保证 |
| 顶层塞进角色卡 | 若 ① 世界设定误入 ④，角色卡无限膨胀、视角失效；靠分层边界防止 |
| 导演越权写台词 | 违背涌现优先铁律；Prompt 显式禁止，护栏兜底 |
| 未来 Book 迁移 | ① 内容暂时冗余在角色卡模板 → 将来抽到顶层实体，模型预留腾挪 |
