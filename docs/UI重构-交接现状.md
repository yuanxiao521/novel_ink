# 墨卷（novel_desk-agent）正文协作 UI 重构 · 交接文档

> 给 UI/UX 设计 agent 的现状交接。请基于这份事实给出「正文协作两模式解耦」的界面方案。
> 技术栈：React 18 + Vite + TS（无 UI 库，手写 CSS，深色纸墨主题），FastAPI 后端。
> 约束：改动以**信息架构与交互重构**为主，后端数据模型尽量不动（可加少量聚合接口）。

---

## 1. 产品是什么

单作者 C 端网文写作工具。核心流程：**主笔**（建书/骨架/卷章/场景/角色）→ **导演台**（多角色
实时推演出剧情，涌现式）→ **正文**（把场景写/演进成小说正文）→ **逐章校对/阅读台/导出**。

## 2. 核心矛盾：正文有两条创作通路，但 UI 把它们混在一起

### 通路 A：直写模式（作者主导）
- 页面：`/write/:chapterId`（章级写作台）
- 动作：作者点「✍ 写这一章」→ 写手 LLM 按章目标/张力曲线/前情逐段写；作者可改、可让责编
  （副驾对话）按建议出**改稿候选**、逐条采纳；保存走版本链（可回退）
- 数据落点：`chapters.prose_md`（章正文，唯一真源）+ `chapter_revisions`（版本）
- 粒度：**段**（一段一个瞬间）

### 通路 B：涌现模式（导演台推演）
- 页面：`/director/:sceneId`（导演台，另一个独立页面）
- 动作：选角（主角/配角/反派 ≤3）→ 播放/单步推演 → 每回合产出：角色行为卡 + 实时旁白
  （写手生成 180-280 字）+ 导演提示；可回退到任意来回重演；「✒ 定稿入库」把各拍旁白
  聚合成 `scenes.final_prose`（**场景级**）
- 数据落点：`scenes.final_prose`（场景级）+ `simulation`（回合归档：行为/思考/张力）
- 粒度：**拍**（一回合一段，连拍后一段可含 3 角色 × 2 来回的全部内容，段落很厚）

### 解耦痛点（作者原话级）
1. **两条通路的数据不相通**：导演台定稿写的是场景级 final_prose，写作页显示的是章级
   prose_md —— 作者在写作页**看不到涌现产出了什么**，要自己去别处复制粘贴「并入」。
   没有任何显式的「并入章正文」动作。
2. **两个页面职责重叠**：写作页里还藏着一个「场景精修」二级页（/studio/:sceneId，
   v1.43 时代的场级工具页），与章级工具重复，入口又深。
3. **模式无标识**：章有 `mode` 字段（draft=rehearse=manual），但 UI 不突出——作者不知道
   "这一章该走哪条路"。

## 3. 现状页面清单与信息过载实测

### 3.1 章级写作台 /write/:chapterId（问题最重的页面）
- **顶栏 15 个按钮**：✍ 写这一章 · 🧩 补全设定 · 🔍 章后巡检 · 🕘 稿本 · 🩺 体检整章 ·
  🗂 审稿会 · 🧭 遵循度 · 🎨 润色整章 · 🔍 质检整章 · 📊 评审整章 · 🧪 AI味(整章) ·
  🔭 看本章上下文 · 🖊 场景精修 · ✎ 编辑 · 💾 已保存
  （其中 🩺🔍📊🧪 等 7 个收在「精修工具 ▾」下拉里，但对作者仍是 15 个可见入口）
- **右栏「本章副驾」**：3 个 tab（责编=对话流+过程卡 / 遵循度=审计报告 / 进度·审校）
- **主区**：整章正文段落（可选中 → 弹出问责编/改稿浮动条）+ 候选卡（未落库预览 + 采纳）
- **顶部还有**：场景切换器、模式徽标、字数/段数、55 条待处理批注提示（曾因 bug 泄漏）
- 作者实测反馈：「太多按钮，画面上太多信息，根本不知道读哪里」

### 3.2 导演台 /director/:sceneId
- 三栏：左=角色栏（选角/状态/信念）· 中=世界黑板（环境事实/当前回合事件/角色状态摘要，
  可切成文页）· 右=导演控制台（张力指数/导演提示/介入工具：注入事件·信息曝光·调整权重/
  护栏状态/与导演共创对话）
- 底部：时间线（回合节点=归档，可点看快照、可回退重演）+ 播放/单步/重放
- 右下角浮层：剧本台/作者工作台/读者阅读台 三个视图切换
- 独立浮层页：剧本台（回合剧本体+高光采纳）、读者阅读台

### 3.3 场景精修（二级页）/studio/:sceneId
- v1.43 的场级工具页：写手初稿/精修工具/批注/责编对话——与章级功能大面积重复，
  v1.65 合并后成为"二级精修页"，但入口仍挂在写作页顶栏，作者会误入。

### 3.4 其它相关页
- 逐章校对 /proofread：每章场景清单/字数/定稿状态/一键去改
- 阅读台（导演台内视图）/ 概览页导出成书

## 4. 数据模型事实（供设计参考，不改模型）

- 章：chapters（prose_md 正文、mode 生产方式、word_target、digest_json 前情）
- 场景：scenes（final_prose 定稿、plan_cfg_json 含 beats 必然事件/导演配置、beats_status）
- 推演：simulation（turn_archives：每来回=张力/摘要/行为/成文/思考）
- 批注：prose_annotations（段落级，状态 open/handled）
- 版本：chapter_revisions（保存即自动存版）
- 工具链：责编 Agent 有一套工具（体检/质检/润色/AI味/评审/审计/改稿/批注处理…），
  均走"右栏过程卡"输出

## 5. 已知 UI bug 清单（近期实测，设计时须一并考虑）

- 成文粒度不一致：前文短段 vs 涌现厚段，finalize 拼接后节奏断裂（计划：写手一拍拆 2-3 自然段）
- 同类信息多处出现：如"字数"在顶栏/校对页/概览各算一遍；审计入口有 2 个（顶栏+右栏 tab）
- 视图切换浮层（剧本台/工作台/阅读台）曾压住时间线节点（已修，但"视图切换"的 IA 仍混乱）

## 6. 设计目标（与作者对齐的方向）

1. **两模式显式解耦**：作者进入一章时明确"这章用直写还是涌现"，两种模式各自有**专属且干净**
   的主界面；模式切换是显式动作（带数据迁移提示），不是藏在下拉里的徽标
2. **涌现产物必须能"并"**：设计一条显式的「场景定稿 → 并入章正文」流（预览 diff/插入位置
   可选/并入后版本链记录），让作者在写作页能看到并管理涌现产出
3. **写作页减负**：15 按钮 → 主路径（写/续写/采纳/保存）+ 一个统一的「审稿/工具」抽屉
   （按章节状态出现）；场景精修要么并入章级要么从顶栏移除
4. **导演台保持"驾驶舱"密度**（这是推演工具，信息密度是特性），但把"视图切换"的 IA 理顺
5. 保留深色纸墨主题与现有设计语言（衬线标题/等宽数据/金色强调）

## 7. 交付期望

- 两模式的信息架构图（含页面归属：哪些功能留在哪、哪些合并、哪些删除）
- 写作页（直写模式）的高保真线框：主路径第一步可见，工具抽屉的层级
- 「并入章正文」的交互流（含冲突/回退处理）
- 导演台只做 IA 微调建议（不强求重画）
- 标注每项改动的实现代价（纯前端 / 需要新后端接口）
