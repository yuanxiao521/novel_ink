# 优化方案 S1 · 世界状态账本（World State Ledger）

> 版本 v0.1 · 2026-09-13
> 上位文档：`docs/写作痛点清单与优先级.md`（S1 · 世界状态漂移）
> 依赖现状：`service.py`（`_bookkeep_after_save` / `_apply_verify_bookkeeping` / `save_scene_prose`）、`chardacters/scene/foreshadow/belief` 四表、`engine/prose.py::verify_prose`、`config.py`
> 目标：给"战力 / 金钱 / 道具链 / 时间锚 / 关键数字"建**可溯源的账本**，写入 && 读入写手感知，根治"前后数值/道具/时间漂移"。

## 1. 现状盘点（真实代码对照）

### 1.1 已有的账本（可复用范本，不重建轮子）

| 账本 | 表 | 三态/溯源性 | 现役写入点 |
| ---- | ---- | ---- | ---- |
| 伏笔 | `foreshadows` | ✅ buried/in_progress/closed + `expected_close_scene` | `_bookkeep_after_save` / `analyze_scene_close` |
| 信念 | `beliefs` | ⚠ 单状态，但含 `char_id/fact_id/source_event_id/编辑标记` | `_apply_verify_bookkeeping`（belief channel） |
| 审计 | `prose_notes` | ✅ `payload_json` 存结构化明细 | 各 prose_* 步骤 |

**关键结论**：`beliefs` 的"宽引用 + 溯源字段"结构（`char_id` 不强制 FK、`fact_id/source_event_id` 可追踪、`edited` 供作者手改）**正是世界状态表要抄的模板**。世界状态表应比照 beliefs 而非新造结构。

### 1.2 缺失的部分（S1 要补的）

| 维度 | 现状 | 缺失 |
| ---- | ---- | ---- |
| 角色现状 | `characters` 只有静态 `spec_json`（性格腔调底线），**无"此刻在哪/状态/势力值/带什么"** | 动态状态字段 |
| 资源/道具 | 无 | 道具持有没有建账，丢了/拿到没记录 |
| 时间锚 | 无 | 场景无"发生第几天"标记，旅行时间不符世界观 |
| 术语表 | 无 | 同一概念前后叫法漂移（灵石/结晶） |
| 关键数字 | 无 | 年龄/战力/金额/境界每次即兴编 |

### 1.3 现役记账链路的复用点（最重要）

```
作者保存正文
   ▼
service.save_scene_prose()          # 幂等，保存后触发
   ▼
_bookkeep_after_save(scene_id,text) # 后台非阻塞；失败只告警不影响落库
   ▼
verify_prose(text, foreshadows, beliefs)   # LLM 现只产 foreshadow_updates/belief_deltas/causal/risks
   ▼
_apply_verify_bookkeeping(book_id, opinion)  # 落伏笔/信念表 + 审计
```

**S1 的侵入点**：让 `verify_prose` 的 schema **并增一栏 `state_deltas`**，`_apply_verify_bookkeeping` **并增一段"写世界状态表"**。这样**一条 LLM 调用同时产出伏笔/信念/状态三份账本**，零新增 LLM 往返、完全复用现有记账触发器。

---

## 2. 目标

- **写入**：正文保存后，从 `final_prose` 提取「世界状态变化」（谁战力突破、谁解锁新道具、又过了几天、新提了哪个术语），落成**可追溯的状态账本**（同一次正文产出，伏笔/信念/状态三表一起更新）。
- **读入**：写手/体检/质检感知时，**只取"跟本场景/当前进度相关"的状态**进 prompt，防止"一次灌全书状态"。
- **幂等 & 可审**：同内容保存不重复记账；每条状态带 `书 id/来源事件/时间戳`，作者可手改。

---

## 3. 设计方案

### 3.1 新表：`world_states`（比照 `beliefs` 模板）

```sql
-- world_states（世界状态账本 · 单状态 append-with-upsert）
id          TEXT PRIMARY KEY              -- 稳定 key：(book_id,kind,key) 哈希
book_id     TEXT  NOT NULL FK books       -- 归属书
kind        TEXT  NOT NULL                -- character|item|time|term|numeric
name        TEXT  NOT NULL                -- 状态对象名（角色名/道具名/时间锚名/术语/数字名）
key         TEXT  NOT NULL                -- 语义键（用于幂等 upsert，如 char:林尘:境界）
value       TEXT  NOT NULL                -- 当前值（如 '元婴初期' / '3' / '灵石'）
scene_no    INT   DEFAULT 0               -- 记录于第几场景（时间序）
source_event_id TEXT DEFAULT ''          -- 溯源：PROSE_SAVE etc.
previous_value TEXT DEFAULT ''           -- 上一个值（用于体现变化，append 的前值）
edited      BOOL  DEFAULT false           -- 作者手改标记
ts          BIGINT                        -- 时间戳
UNIQUE(book_id, kind, key)                -- 幂等 upsert 依据
```

> **选 append 还是 upsert？**（项目设定的权衡）：
> - 现役 `beliefs` 是 **upsert 单态**（按 key 幂等覆盖）；`foreshadows` 是**三态生命周期**。
> - S1 对照"现阶段"取**upsert 单态 + previous_value 保留前值**（够用：写手只读"当前值"，溯源靠 `source_event_id`+`ts`）。
> - 若后续要"查剑什么时候丢的"完整时序，再升级成 append-only 事件流（记入 S1 扩展，见 §5）——避免现在为一个还不存在的需求复杂化。

### 3.2 `verify_prose` schema 扩展端（engine/prose.py）

在现 schema（`foreshadow_updates/belief_deltas/causal/risks`）上并增：

```json
"state_deltas": [{
    "kind": "character|item|time|term|numeric",
    "name": "str 状态对象名（林尘/屠龙剑/第3天/灵石/境界）",
    "key": "str 语义键（char:林尘:境界 / item:林尘:剑 / time:全书:当前日 / term:通用:灵石 / numeric:林尘:战力）",
    "value": "str 当前值",
    "previous_value": "str 前值（可为空）"
}]
```

- 校验器 `VERIFY_VALIDATOR` 同步扩充：`dict` 需含 `state_deltas` 键；`state_deltas` 内每项含 `kind/name/key/value`。
- `verify_prose()` 的 `foreshadows/beliefs` 参数外**再传 `world_states`**,让 LLM「对照既有状态→只报变化」,避免全量重复上报。

### 3.3 写入端（service.py `_apply_verify_bookkeeping` 扩展）

在现"1)伏笔 2)信念"后加 **3)世界状态**，复用同一 `written` 计数与幂等模式：

```python
# 3) 世界状态（upsert，比照信念）
for s in opinion.get("state_deltas") or []:
    kind, name, key = s.get("kind"), s.get("name"), s.get("key")
    value = str(s.get("value") or "").strip()
    if not (kind and name and key and value):
        continue
    nid = hashlib.sha256(f"{book_id}|{kind}|{key}".encode()).hexdigest()[:16]
    rid = f"ws-{nid}"
    prev = STATE_CACHE.get(key, s.get("previous_value") or "")  # 或按 id 查库取当前值
    await self.repo.upsert_world_state({
        "id": rid, "book_id": book_id, "kind": kind, "name": name, "key": key,
        "value": value, "scene_no": scene_no, "source_event_id": source_event_id,
        "previous_value": prev, "edited": False, "ts": int(time.time() * 1000),
    })
    written += 1
```

> 幂等闸门：由"同 text 重复保存 unchanged 不触发"（`save_scene_prose`）天然保证；`UNIQUE(book_id,kind,key)` 兜底 upsert，不重复插行。

### 3.4 感知端注入（写手/体检/质检）

- **写手 `prose_draft`**：在现有 `characters` + `prev_prose` 前，注入**相关世界状态**（本场景出场角色的 `character/item/term` + 书级 `time/numeric` 相关项）。裁剪规则：**按 kind+name 过滤**，而非全量——"只喂跟当前角色/当下相关的状态"。
- **`chief_perceive`**：新增第 6 段"世界状态现状（写作用的状态骨架）"，只取 `edited=false`（作者没手改=默认真实）的关键若干条。
- **体检 `prose_review` / 质检 `prose_verify`**：把 `world_states` 传给 LLM，使其可比对"正文物 vs 账本数值是否一致"→ 发现漂移直接报 `risks`。

## 5. 验收标准（可测）

1. **单元**：保存正文后，`world_states` 有对应 `kind=character/item/time/term/numeric` 的行，`source_event_id=PROSE_SAVE`。
2. **幂等**：同 text 再保存一次 → `unchanged=true`，不重复写 `world_states`。
3. **回流**：用 `--live` 跑一次"保存正文 → `_bookkeep_after_save` → `list_world_states`"，确认状态能喂回 `prose_draft` 的 prompt（日志可见）。
4. **一致性体检**：给一段"主角战力与前账本冲突"的正文，`review_prose` 能在 `risks` 指出漂移。
5. **回归**：pytest（FakeLLM）全绿；`foreshadows`/`beliefs` 记账行为不回退。

## 6. 明确不做 / 触发条件

| 不做 | 原因 | 触发何时纳入 |
| ---- | ---- | ---- |
| append-only 完整时序流 | 现阶段 upsert+previous 够用，不提前复杂化 | 需"回溯剑何时丢/状态历史演绎"时升级 |
| 关键数字表全量自动校验 | 依赖"提取"稳定；正文被作者大改时账本失真 | 首本样本验证提取可靠后 |
| 多角色/多时间线并存 | 单线网文未遇；复杂结构是 S3 全局视角范畴 | S3 展开时再看 |
