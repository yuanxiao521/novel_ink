# 优化方案 A2 · 质量回环（自评 → 门控 → 定点重写 → 复检）

> 版本 v0.1 · 2026-09-13
> 上位文档：\`docs/写作痛点清单与优先级.md\`（A2 · 质量不稳定，等级 A）
> 一句话：把"一次成稿、写坏了没人拦"变成**初稿自评 → 低于阈值自动重写 1 次 → 复检门控 → 不达标就回退**。
> 关键前提：**不造第二套重写通道** —— 重写复用 A3 已交付的 \`engine/ai_tone.py::spot_fix\`（结构化重写 + 事实闸门 + 双闸复检 + 幂等/回退），A2 只新增"评分与门控"。

## 2. 目标

1. **自评**：初稿后由**独立评审员**（不复用写手上下文，避免自我背书）给出各维度分数 + 弱项列表；
2. **门控**：总分 < 阈值（默认 70）→ 自动触发**一次**重写（硬上限 1 次，防烧钱/防循环）；
3. **重写**：复用 A3 \`spot_fix\`（定点改命中句）；弱项若判定为"节奏/结构"类（无具体命中句）→ 走**一次全文重写**分支（同样受闸门约束）；
4. **复检**：分数必须**上升** 且 事实不变 且 口吻不劣化 → 才采纳；否则**回退初稿**并如实记录"改不动"；
5. **可追溯**：评审/重写/复检明细落 \`prose_notes.payload_json.quality\`。

## 3. 设计

### 3.1 评分器（硬信号 + LLM 双段）

\`\`\`
QUALITY_SCHEMA = {
  scores: {coherence, character_consistency, pacing, imagery, ending},   # 各 0-100
  total: int,                     # LLM 自评总分 0-100
  weak_points: [{dim, evidence, why}],   # 必须带正文原句（逐字），防空评
  verdict: "pass|revise"
}
最终分 = round(LLM.total * 0.7 + 硬信号分 * 0.3)
硬信号分（0-token，复用既有）：
  · 文风：ai_tone_report.counts.total / hit_score.terms（命中越多扣越多）
  · 口吻：voice_prior 的 per_char 句长/语气词异常（与卡内腔调背离）
  · 状态：与 world_states 的术语/数字冲突（verify 的 risks 命中数）
\`\`\`

- **要求打分必须带证据**（\`evidence\` 逐字原句，复用 A3 的 quote 规范化），无证据的弱项丢弃 —— 防止"编造问题骗重写"；
- 体检 \`issues\` 可直接作为 \`weak_points\` 输入（D6，省一次往返）。

### 3.2 门控与重写（复用 A3 通道）

\`\`\`
if 最终分 >= 阈值 or verdict == "pass":  # 默认 70
    return {accepted: false, reason: "未触发（分数达标）"}   # 不改文、不花钱
elif 有可定点弱项（命中句/证据句）:
    out = await spot_fix(...)             # A3 通道：定点改 + 事实闸门 + 双闸复检
else:                                     # 结构性弱项（如 pacing 全篇）
    out = await 全文重写一次（同 prompt 约束 + 事实闸门 + 口吻闸门）
\`\`\`

- **硬上限 1 次重写**：无论结果如何都不再循环（防"越改越糟"与成本失控，C1 再谈并行/多次）；
- 全文重写分支也必须过 **事实闸门 + 口吻闸门**（复用 A3 的 \`fact_gate\` / \`_voice_not_worse\`）。

### 3.3 复检（三闸）

| 闸 | 判据 | 不满足时 |
| -- | -- | -- |
| 分数 | 复评总分 **严格上升**（≥ +3，避免噪声抖动） | 回退初稿 |
| 事实 | 专名/数字/术语/引号内台词逐字一致（A3 \`fact_gate\`） | 丢弃该次重写 |
| 口吻 | 角色平均句长变化 ≤40% 且不新增语气词（A3 \`_voice_not_worse\`） | 回退初稿 |

### 3.4 落点与接口（并增）

- \`POST /scenes/{id}/prose/quality-loop\` → \`{before: {scores, total}, after: {...}, accepted, rewritten: "spot|full|none", changes, reason}\`；
- 采纳时落 **polisher note**（before/after）→ 复用前端"应用"管线（与 A3 spot-fix 一致）；
- 评分明细（含硬信号构成）落 \`payload_json.quality\`。

### 3.5 前端（并入正文协作面板）

「🎯 质量回环」按钮 + **分数卡**：各维度条形 + 总分行 + 弱项列表（带原句）+ 结论（采纳/回退/未触发）+ 「✓ 应用改写」。**不做**：一键全文重写按钮（避免绕过闸门）。

## 5. 验收标准（可测）

1. **评分可复现**（假 LLM）：固定输入 → 分数/弱项稳定；**无证据的弱项被丢弃**；
2. **门控正确**：高分（≥阈值）→ **不重写、不调 LLM 重写分支**（省成本）；
3. **低分触发一次**：低分 → 走 spot_fix；**最多 1 次**重写（计数用假 LLM 断言调用次数）；
4. **三闸复检**：分数未上升 / 事实被改 / 口吻劣化 → **回退初稿**且给出原因；
5. **硬信号参与**：文风命中多/状态冲突多时，最终分显著低于纯 LLM 自评分（构造对比）；
6. **落库契约**：note 的 \`payload_json.quality\` 含 before/after 分数与硬信号构成；
7. **LLM 不可用**：明确提示且不改文；
8. **回归**：全量 pytest 全绿；S2/S3/S4/A3 行为不回退。

## 6. 明确不做 / 触发条件

| 不做 | 原因 | 触发何时纳入 |
| -- | -- | -- |
| 无限循环重写直到达标 | 成本失控 + "越改越糟"风险 | 需要时改成"作者手动再跑一轮" |
| 多评审投票（3 个 reviewer 取均值） | 3× 成本，收益未验证 | 单评审与人判偏差大时 |
| 章节级批量门控 | 属 C1（性能/并行）范畴 | C1 展开时一并 |
| 把质量分写进账本/新表 | 审计明细落 payload 足够 | 需要"质量趋势曲线"时（可挂到 S3） |
