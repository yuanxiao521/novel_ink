主笔 ↔ 责编：信息怎么流（下行约束 / 上行信号 / 按需复盘）

不是"主笔盯着责编"，也不是"写完就自理"；两者只能建议，不能互相直接改
主笔 书级
掌管结构与约束：书树 / 节奏 / 伏笔 / 角色弧 / 方向·世界观·硬规则
不能改正文
① 下行 · 约束（已有，且是"全员读"）book → scene已实现
约束表（方向/世界观/硬规则/节奏/信息） · 书树（本章本场目标） · 伏笔计划 · 建议彩排
形式：只读约束 + 场景任务，不是逐句指令
② 上行 · 场景信号包（结构化，不是全文回灌）scene → book缺
字数达成（实际 / 目标） · 本场张力（回合归档） · 伏笔（埋了没 / 收了没） · 角色口吻偏离（voice_findings） · 批注热点（哪类问题反复出现） · 重写次数 / 被驳回项 · 偏离场景目标（质检 risks）
现状断点：prose_notes 里有这些原始记录，但只给人看，agent 不读
③ 横向 · 请求-应答（L3 任务总线）scene → 场记/角色缺
责编："这场没把握，请求彩排" → agent_tasks → 编排者派给场记/角色 → 素材回填本场（勾选才注入）
责编 本场
掌管这一场的文字：正文 / 口吻 / 事实一致 / 伏笔落地 / 读批注
不能改骨架与约束

④ 主笔什么时候读上行信号按需，不打断

作者召唤时（主笔对话 / 让主笔排骨架）→ 读汇总视图，不是逐条原文
作者在概览点「让主笔复盘」 → 读全书信号 → 产出约束修订建议 / 骨架调整建议
场景收束时 → 只落信号（不自动叫主笔），避免打断作者心流
产出永远是"建议 + 确认"，主笔不会自动改骨架

实现：不新建表（沿用 S3 纪律）

数据源已存在：prose_notes（kind/status/created_by）+ TurnArchive.tension + 批注状态 + final_prose 字数
做法：在 S3 global_view.py 上加一段0-token 派生的「写作侧信号」（统计 + 热点），与曲线/诊断同源
三个落点：正文保存后（已有 _bookkeep_after_save 钩子）· 场景收束 · 概览复盘
好处：零新表、可回放、可测试（纯派生）；主笔的上下文只多"一段摘要"

为什么不用另外两种

方案一 · 单向（现状）：主笔给完约束就不管 → 第 4 章才发现第 1 章跑偏，已经太晚；"主笔掌管一切"变成一句口号
方案二 · 全文回灌：把正文全塞回主笔 → 上下文爆炸，且主笔会忍不住改句子（越界），与责编互相覆盖
方案三 · 信号上行（选它）：场景层给结构化的"发生了什么"，主笔给结构化的"接下来该怎么"——各管一层，靠信号与建议衔接
