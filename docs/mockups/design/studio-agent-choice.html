正文协作的 agent：复用主笔，还是新建？

"复用"该发生在能力层（工具 / 约束 / 账本 / 审计），不该发生在人格层

A · 新建「责编」，共享底座建议

选它：职责分层，能力全共享 —— 用户看不出重复，系统不会串味
共享（一套实现）
  • 书级约束表：方向 / 世界观 / 硬规则 / 节奏 / 信息
  • 工具集：同一份 ToolRegistry
  • 三本账读取：同一裁剪视图
  • 审计：同一 prose_notes，只记"谁发起"
  • 模型档位 / 事实闸门 / 校验层
专属（各自差异）
  • system prompt：总编（结构）vs 责编（本场文字）
  • 感知 scope：书级（树+诊断）vs 本场（正文+批注+事实）
  • 记忆域：书级记忆 / 回合史 vs 本场工作记忆+批注
  • 产物落点：骨架 / 角色卡 vs final_prose + 批注
成本：多一个 AgentSpec + 一段 system prompt。几乎为零（底座本来就要建）

B · 直接复用主笔（一人格跨页）不建议

不要：等于让总编下到句子级，两个优势同时丢
后果
  • 上下文膨胀：一个 prompt 要塞 书树+全书诊断+本场正文+批注
  • 俯瞰优势丢失：总编最值钱的是全局视角
  • 无法归因：分不清是"结构错"还是"句子错"
  • 对话史混淆：全书规划与"这一段改一下"混在一条会话里
  • 约束失效：主笔既是规则制定者又是执行者，没人把关
唯一好处：少写一个 agent —— 省下的成本远小于上述代价

C · 同一 agent、两个视角过渡方案

可作过渡：双 system prompt（书级 / 场景级）切视角
比 B 好的地方
  • prompt 不混，感知可按 scope 给
  • 工作量最小（复用对话通道）
仍存在的问题
  • 对话史与记忆域仍共享 → 容易糊
  • 审计里"谁说的"区分不清
  • 下一步拆分时要迁数据
只在"想先看效果、一周内要上线"时才选它

落地时具体长什么样

用户可见主笔页顶部 = 「主笔 · 书级」；正文协作页右栏 = 「责编 · 本场」——两个身份、两个入口，同一个工具箱
后端两份 AgentSpec（主笔 scope=book / 责编 scope=scene），共用 ToolRegistry · ToolExecutor · 约束表 · 三本账读取 · 审计
约束谁说话主笔维护约束表（书级资产），全员读——这就是你要的"主笔掌管一切"，靠约束生效，而不是靠一个 agent 跨页乱改
彩排请求责编用 agent_tasks 发起 → 编排者派给场记/角色 agent → 产物回填本场（C 批第一条真实任务单）
