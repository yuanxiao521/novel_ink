# Agent 与 LLM 能不能一起训练？—— 机制、可行性与墨卷落地路径

> **定位**：回答一个理念性问题 —— 「LLM 训练完参数就冻结了，那上层 agent 有什么可训练的？能不能不训 LLM，而是把 agent 训练起来？甚至把 agent 与 LLM 当成一个东西一起训？」
> **一句话结论**：**LLM 是冻结的『函数』，agent 是可改的『控制器』**。二者能一起优化的部分，今天只有『策略那一段』，而且要靠**数据 + 搜索 + 小模型**，不是靠一张统一的反传图。端到端联合训练在研究上存在，工程上没有通用落地方案。
> **日期**：2026-10-04 · 本文是讨论记录，不改变主线（S/A/B/C 之外的 T 系列待考虑项池同样适用）。

---

## 0. 先把两个「涌现」分开

| 说法 | 含义 | 能不能「训练出来」 |
| --- | --- | --- |
| **模型能力涌现**（emergent abilities） | 规模/数据到某个量级后，模型突然会做多步推理、算术、指令跟随（Wei et al. 2022 那类观察） | 是**规模化训练**的副产品，不是训练目标；无法「定向涌现」 |
| **墨卷的「涌现式小说」** | 多 agent（角色×主笔×责编×场记）+ 世界状态账本 + 硬边界约束，在推演中产出**没人预先写好的情节** | 是**系统级涌现**：优化变量是**规则、信息结构、约束、评分与反馈回路**，不是权重 |

这两件事常被混为一谈。你的项目属于后者：它的「学习」发生在**账本与记忆**里，不发生在参数里。这恰好也是本文的起点。

## 1. LLM 底层：一次前向传播里有什么，训练改了什么，推理期什么还能变

### 1.1 一次 forward 的零件（以 decoder-only Transformer 为例）

```
tokens → id → embedding 表 (V × d)          ← 离散 token 的连续向量
  ↓  重复 N 层：
  RMSNorm → QKV 投影 (Wq, Wk, Wv: d×d)
          → 多头注意力 softmax(QKᵀ/√d_k)·V（因果掩码）
          → 输出投影 Wo → 残差
  RMSNorm → FFN（SwiGLU：W_gate, W_up, W_down，中间维度约 2.7–4d）→ 残差
  ↓
lm_head (d × V) → logits → softmax → 采样（温度 / top-p / top-k）→ 下一个 token
```

- **参数分布**：FFN 约占 2/3 参数（**事实性知识主要沉淀在这里**），注意力约占 1/3（检索、复制、指代、长程依赖）。embedding 与 lm_head 常共享权重。
- **KV cache**：推理时缓存每层 K/V，避免重算；序列越长显存与时间越线性增长 —— 这是「长上下文很贵」的物理原因，也是你 `perceive.py` 要裁剪留痕的原因。
- **它本质是什么**：一个**条件概率模型** P(next token | 前文)。它没有「数据库」，也没有「变量」；所谓「记忆」是参数里的连续表征与上下文里的临时激活。

### 1.2 训练改的到底是什么

| 阶段 | 目标函数 | 改了什么 | 没改什么 |
| --- | --- | --- | --- |
| 预训练 | next-token 交叉熵 | 世界知识的统计压缩 + 语言结构 | 不产生「可寻址事实库」 |
| SFT / LoRA | 也是 next-token CE，但数据是「指令→答案」 | 把分布往指令跟随、格式、语气上推 | 不新增知识（除非数据里有） |
| RLHF / DPO / KTO | 偏好（人类或 AI 打分） | 「在多个候选里选哪个」的倾向 | 不保证事实正确 |

三个必须记住的结论：

1. **训练不新增可寻址记忆**：让模型「记住这本书的设定」是错误期望，参数会覆盖、会遗忘（灾难性遗忘）。**设定/世界状态必须放外部**（你的 `world_states` / `beliefs` / 记忆四层就是正确做法）。
2. **训练会丢东西**：SFT/RL 过后通用能力会退化，所以工业界做 LoRA + 小学习率 + 混通用数据 + 每轮回归评测。
3. **推理期「学习」只有三个去处**：上下文（ICL）、外部状态、工具。下面这张表就是 agent 的全部可优化空间。

### 1.3 推理期能变的三样东西

- **上下文（ICL）**：prompt、示例、检索证据、约束表 —— 最便宜、最有效、可即时生效的「权重」。
- **外部状态**：L1 黑板（`SimulationState`）/ L2 账本（PG）/ L3 任务总线 / 记忆四层 —— 这就是你的「可写权重」。
- **工具与动作空间**：加一个工具 = 扩大能力上限，不需要训练（你 A→E 批 16 个工具 + `ToolExecutor` 就是这条路的红利）。
- 附带一个：**test-time compute**（多采样/自洽/投票/验证器）。你的审稿会 + 评审 + `quality.py` 就是验证器，属于「花算力换质量」，同样不需要训练。

### 1.4 补充：「参数冻结」到底发生在哪一步？训练资料是不是「冻进参数里」了？

先纠正一个措辞：**训练的时候参数不是冻结的，恰恰相反 —— 训练就是在改它们。**「冻结」只发生在三处：

| 场景 | 谁被冻结 | 具体做法 | 为什么 |
| --- | --- | --- | --- |
| 推理 / 部署 | **全部权重** | 权重只读（bf16/fp16/fp8 放在显存），只有 KV cache 与上下文在变 | 你要的是稳定输出，不是边服务边改参数 |
| LoRA / 适配器微调 | **底座权重** | `W.requires_grad_(False)`，只训旁路 A/B | 省显存、抗遗忘、可插拔 |
| 迁移学习 / 部分微调 | 前 N 层、embedding、或除 lm_head 外全部 | 分层设置 `requires_grad` | 保住通用能力，只调任务头 |

#### 一个最小例子：资料怎么「变成数字」

目标：学会 `y = 2x + 1`。初始 `w=0, b=0`，学习率 0.1，拿一条样本 `(x=1, y=3)`：

```
预测 ŷ = w·x + b = 0        → 误差 e = ŷ − y = −3
梯度   ∂L/∂w = 2·e·x = −6    ∂L/∂b = 2·e = −6
更新   w ← 0 − 0.1·(−6) = 0.6   b ← 0.6
再拿同一条样本：(1) → ŷ = 1.2，误差变小 …… 反复若干次 → w≈2, b≈1
```

**这条样本没有「存」在任何地方，它只是把两个旋钮拧到了某个位置。** 换一批数据来训，旋钮会停到别的位置。

#### 换到 LLM：一次 next-token 的更新

训练语料里的「北京是中国的首都」，会被切成多个「给定前文 → 预测下一个 token」的样本，例如给定 `北京是中国的` 预测 `首都`。模型输出的是词表上的 logits，经 softmax 得概率，损失是交叉熵：

```
logits:  首都 2.0   上海 1.0   广州 0.5  →  softmax ≈ 0.66 / 0.24 / 0.10
loss = −log(0.66) ≈ 0.42
反传：把 `首都` 的 logit 推高一点点，把 `上海/广州` 压低一点点
这些「一点点」落在 Wq/Wk/Wv/Wo、FFN 的 W_gate/W_up/W_down 里 —— 就是成千上万个 fp16 数字的微调
```

重复这条样本若干次（或多个 epoch），「首都」在这个上下文下的概率就稳定高于「上海」。**所谓「知识」，就是数万亿次这样的小位移累积出来的权重形状。**

#### 那「资料」到底在哪？

| 问题 | 答案 |
| --- | --- |
| 是原文存进参数了吗？ | **不是**。是**有损压缩**：约 15T token（数十 TB 文本）压进 ~14GB 权重，压缩比千倍级；所以模型会「大致说对」，但精确日期/编号/人名经常错 |
| 能定位到「巴黎＝法国首都」存在哪个权重吗？ | **不能**。知识**分布式叠加（superposition）** 在成千上万个维度上，没有「第 731 行」这种寻址（模型编辑 ROME/MEMIT 只能在极小范围内改，且有副作用） |
| 一个字也没逐字记下来吗？ | 被**重复足够多次**的串会近似逐字复现（这正是「抽取攻击/版权泄露」的原理）；但那是副作用，不是设计意图，也不可控、不可删除 |
| 训练资料本身「冻结」了吗？ | 没有。数据在训练中被反复读取后就被**消费掉**了；推理时数据文件完全不参与。训练结束被冻结的是**权重**，不是数据 |
| 那「临时参数」在哪？ | **上下文 + KV cache**：会话内的「可写区」，会话一结束就消失 —— 这就是为什么你的记忆四层/账本是「可写权重」，而权重只管语言能力与风格 |

#### 「冻结」长什么样（LoRA 的具体数字）

以一层 `d=4096` 的投影矩阵为例：

```
全量微调：W(4096×4096) = 16.7M 可训参数，优化器要存 2 个动量 fp32 ≈ 每参数 8 字节
LoRA(r=16)：W 冻结；新增 A(16×4096)+B(4096×16) = 131K 可训参数（0.78%），ΔW = B·A·(α/r)
→ 7B 全量微调：权重14GB + 梯度~28GB + 优化器状态~56GB ≈ 100GB 级
→ 同模型 LoRA：优化器状态降到 MB 级，单卡可做
```

#### 对墨卷的三条直接结论

1. **把「多本书的设定」塞进权重是错的方向**：共享权重会让不同书的设定互相污染（串味），而且改一条设定要重训；这也解释了为什么 `world_states` / `beliefs` / 记忆四层必须是外部账本。
2. **权重只负责「语言能力 + 风格」**：语感、角色口吻、叙事节奏适合训（且适合 LoRA）；事实、时间线、伏笔状态必须靠账本 + 检索。
3. **权重更新 = 全局重写，账本更新 = 定向写入**：前者贵、慢、不可逆；后者便宜、可审计、可回滚。所以「让 agent 学」的正确落点是**账本 + 记忆写入策略 + 评估器**，而不是反复微调底座。

## 3. 「把 agent 和 LLM 合成一个东西训练」的四条路线

### 3.1 端到端可微（软提示 / LoRA / latent 推理）

- 做法：把 prompt 里的 token embedding 当可训练向量（prefix/prompt tuning），或挂 LoRA；整条图在**可微**前提下反传。
- 现实障碍：
  1. **离散采样断梯度**：文本回到下一次调用是 argmax/采样，不可微；直通估计 / Gumbel-softmax 只在小动作空间有效。
  2. **credit assignment**：你的审稿会是 4 次 LLM 调用，最后一句好正文该归功于哪一次决策？
  3. **成本爆炸**：一次 rollout = 几十次调用；PPO 要成千上万次 rollout；显存、时长、费用三重天花板；且 `simulation` 有随机性、LLM 有温度 → 环境不可复现。
  4. **你用的是 API**：连第一层梯度都取不到。
- 结论：**理论可行、工程受限**，只在「单 agent + 固定短流程 + 开放权重」时才值得碰。

### 3.2 轨迹 SFT → 偏好（DPO）→ 策略梯度（GRPO/PPO）—— 真正能落地的「训练 agent」

这是工业界主流形态，也是**「agent 与 LLM 变成一个东西」的现实版本**：

```
跑系统（API 模型即可）
   ↓  采集轨迹：(状态摘要 → agent 决策 → 结果 → 作者采纳/驳回 → 质量分变化 → 成本)
   ↓  筛出好轨迹（采纳、质量分↑、回环少、成本低）
数据：SFT 数据集（学「该怎么做」） + 偏好对（DPO：同一状态下 A 比 B 好） + reward（可自动算）
   ↓  在开源底座上加 LoRA 训练 → 你得到一个「主笔/责编」专有模型
   ↓  上线替掉部分 API 调用；编排与提示继续用第 1 档的方法优化
```

- **关键点**：这条路不需要「端到端可微」，因为策略（LLM 权重）和编排（代码/文本）是**分阶段交替优化**的：改了编排 → 产生新轨迹 → 再训策略 → 换回来继续。这就是「联合优化」在工程上的真实含义。
- **reward 从哪来**（你恰好有）：作者采纳率、`quality.py` 质量分提升、回环次数、字数/成本效率、一致性（角色口吻 `style_checks`）。

### 3.3 黑箱编排优化（不改 LLM，先把 agent 变强）—— 性价比最高

- 把「提示模板 + 编排图 + 阈值 + 检索参数」当成**离散参数**，用进化/贝叶斯优化/bandit 搜；用固定评测集打分。
- 也可以用「文本梯度」范式（DSPy 的 compiler、TextGrad 的『自然语言反向传播』、OPRO 的『让模型读分数改进提示』）。
- 为什么先做这个：**不需要权重、不需要 GPU、不需要新服务**，且每一步都有对照数据（符合你「先度量后阈值」的纪律）。

### 3.4 多 agent 联合 RL（研究级）

- 让角色 agent 之间的通信/分工被学出来（涌现式协作、通信协议压缩）。
- 现实问题：环境不可复现、reward 稀疏、成本按 agent 数 × 调用数增长、评估困难、结果常「小规模玩具环境成立」。
- 触发条件：前 1–3 档收益已榨干 + 有稳定可复现仿真 + 有专项预算。**现在不做**。

### 3.5 小结：为什么「一个大网络端到端」不成立

| 硬约束 | 后果 |
| --- | --- |
| 文本是离散采样 | 梯度断在每一次 LLM 调用边界 |
| 长调用链 | credit assignment 无法可靠分配 |
| 成本随调用数指数叠加 | 训不动 |
| 环境随机（温度/仿真） | 复现与评估都不可靠 |
| API 模型 | 权重不可得 |

所以可行形态是：**冻结底座 + 可训小部件 + 数据/搜索驱动编排**，即「分层可训」。

## 4. 墨卷落地四档（含触发条件与验收）

### 第 0 档 · 决策日志（现在就做，零新依赖）

没有数据就没有训练 —— 这是**所有后续档位的前置条件**。

- 记录（JSONL 或新表）：`{任务, 感知包摘要, agent, 建议/动作, 作者采纳?驳回, 质量分前/后, 回环次数, 耗时, token 成本}`。
- 现成原料：`simulation` / `events` / `turn_archives`（含 thoughts）/ `prose_notes(payload_json, kind=tool)` / `agent_tasks` / `agent_messages` / `prose_annotations`。
- 验收：能算出**建议采纳率、单场平均成本、平均回环次数、质量分增量的分布**。

### 第 1 档 · 评测集 + 黑箱编排优化（不改模型）

- 固定 10–20 个评测场景（golden set，含「干净场景」「该润色的场景」「空 cast」「伏笔密集」）。
- 把阈值/提示/是否润色/检索 k/感知裁剪预算当参数，网格或进化搜；每轮出对照表。
- 验收：同评测集上「质量分不降、成本/回环数下降」的可复现曲线。

### 第 2 档 · 评估器小模型化 + 路由蒸馏

- 用第 0 档数据训本地小模型：① 打分/弱项分类（替代部分 `quality.py` 的 LLM 调用）② 下一步路由。
- 收益：省钱、一致性更好、可解释、可离线回归（不必每步都烧 API）。
- 验收：与 LLM 打分的一致率（如 Spearman/一致率 ≥ 阈值）+ 成本下降比例。

### 第 3 档 · 开源底座 + LoRA + 轨迹 SFT/DPO

- 把「主笔」「责编」训成专有模型；数据来自第 0 档（需要数千条高质量轨迹 + 偏好对）。
- 前置：可训底座（Qwen/GLM/Llama 等）、GPU、训练/评测基建。
- 验收：在 golden set 上质量分/采纳率超过 API 基线，或同质量下成本下降。

### 第 4 档 · 多 agent 联合 RL / 端到端可微编排（研究）

- 触发条件：前三档榨干 + 稳定仿真 + 预算；否则不做。

## 5. 五个常见误区（都是这个理念问题的高频坑）

1. **把「记忆」当权重**：记忆只是 ICL 的输入，不写回就永远没「学到」。所以记忆四层必须配**写入策略 + 衰减/遗忘 + 引用反馈**（哪条记忆被引用并最终被采纳，要能反查）。
2. **把「评测」当训练**：`quality.py` 的分数只是 reward 的**代理**；没有「作者采纳」闭环的分数，会奖励「漂亮但空」的文本。
3. **以为 API 模型也能训**：权重不开放 → 只能优化它周围的一切。想训策略必须换/并存开源权重。
4. **忽略灾难性遗忘**：SFT 完通用能力会掉；要做 LoRA、小学习率、混通用数据、每轮回归。
5. **把「涌现」当训练目标**：能力突变是规模现象；你的系统级涌现靠**规则与反馈回路**设计，靠「账本 + 约束 + 评审」而不是靠反向传播。

## 6. 术语表（速查）

| 词 | 一句话 |
| --- | --- |
| Pretraining / SFT | 下一个 token 预测；前者用海量文本，后者用指令数据 |
| LoRA | 冻结原权重，只训低秩旁路矩阵（省显存、抗遗忘） |
| RLHF / DPO / GRPO / PPO | 用偏好或 reward 优化「选哪个回答」；DPO 免 reward model，GRPO 用组内相对优势省价值网络 |
| ICL | in-context learning：不改权重，靠上下文「临时学会」 |
| RAG | 检索外部资料塞进上下文（= 可寻址记忆的正确姿势） |
| KV cache | 推理缓存注意力 K/V，长上下文的成本来源 |
| credit assignment | 长流程里「功劳/责任归谁」，多步 agent 的核心难题 |
| bandit / 文本梯度 | 无梯度优化离散选择；用自然语言反馈改提示 |
| emergent abilities | 规模带来的能力突变（≠ 你的「涌现式小说」） |
| 系统级涌现 | 多主体 + 状态 + 约束相互作用产生的未预设产物（你的项目所在层） |
