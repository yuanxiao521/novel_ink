# 前情压缩设计（前情概要 v1：结构先行）

> 目的：写第 N 章时，模型拿到的不是「前 9 章全部正文」，也不是「一堆检索片段」，
> 而是**分层、结构化、有预算**的「前情概要」。这是长篇一致性的地基。

## 0. 为什么现在的前情不够

| 现状 | 问题 |
| --- | --- |
| 只带「上一章结尾 600 字」 | 保语感，但**不保事实**：第 10 章不知道第 3 章的玉佩在谁手里 |
| RAG 检索章摘要/正文尾 | 抽到什么算什么，**不保证关键状态一定在场**（漏一次就写崩） |
| 章摘要 = 一段自由文本 | 只能"读"，不能"核对"：无法回答"谁知道这个秘密""谁手里有这把剑" |

结论：需要一份**可核对的状态清单** + 一份**可读的叙事摘要**，分层保存、按预算注入。

## 1. 三条设计原则

1. **状态优先于剧情**：写手需要"现在是什么状态"，不是"发生过什么故事"。
   凡是"叙事化"的字段都会诱发模型复述前情（写作大忌），所以剧情只保留极短一句。
2. **可判定**：字段尽量是能核对的事实（谁拿着什么 / 谁知道什么 / 谁在哪），
   而不是形容词（"气氛紧张""关系微妙"）。
3. **分层不重复**：卷级只放**跨章不变**的东西（人物弧线、规则、长线伏笔）；
   章级只放**这一章改变了什么**（增量）。层与层之间不重复描述同一件事。

## 2. 三层结构

| 层 | 覆盖 | 回答什么问题 | 预算（注入时） |
| --- | --- | --- | --- |
| **全书级** book | 全书 0..N 章 | 这本书的人物弧线、核心规则、长期伏笔 | 250~350 字 |
| **卷级** volume | 一段连续章（默认 8~10 章） | 这一卷的核心冲突与转折、本卷人物状态 | 300~450 字 |
| **章级** chapter | 单章 | 这一章**改变了什么**（状态增量 + 钩子） | 150~250 字/章，只注最近 1~2 章 |

注入总量目标：**全书 300 + 卷 400 + 最近两章 400 = 1100 字**，再加 RAG 片段 800 字、
上一章结尾 600 字 → prompt 里前情部分约 **2500 字**（此前仅 600 字，现在可控且有结构）。

## 3. 章级前情概要（digest）字段

```json
{
  "chapter_no": 7,
  "title": "第七章 界墙",
  "one_line": "林澈在界墙被霍岸拦下，路引被当场收走。",
  "events": [
    {"who": "霍岸", "did": "把林澈的路引对折收走", "where": "第一里界墙", "consequence": "林澈失去合法身份"}
  ],
  "state_changes": [
    {"target": "路引", "from": "林澈持有", "to": "霍岸持有"},
    {"target": "林澈·身份", "from": "持涂改路引", "to": "无路引·非法"}
  ],
  "knowledge": [
    {"who": "霍岸", "learned": "路引背面的涂改出自宁秋鹜之手", "how": "比对墨迹"}
  ],
  "facts_established": ["界墙的影迹灯能映出非本人影迹"],
  "foreshadow_touched": [
    {"id": "f3", "action": "advance", "note": "残图线索指向宁秋篙"}
  ],
  "hook": "霍岸临走时叫出了林澈的真名 —— 他到底知道多少？",
  "open_questions": ["谁在路引上做了手脚", "霍岸为何知道真名"],
  "new_entities": [{"name": "影迹灯", "kind": "term", "note": "界墙装置"}],
  "summary_md": "（人读版：150~200 字叙事摘要，给作者/编辑看，不给写手当事实源）"
}
```

字段分工（重要）：

- `events` / `state_changes` / `knowledge` → **给写手**（可核对，防"人设漂移/道具蒸发/信息不该知道却知道"）
- `hook` / `open_questions` → **给下一章**（承接钩子 + 未解悬念，这是网文的命）
- `foreshadow_touched` → **给账本**（与 foreshadows 表互校，推进/回收都在这里留痕）
- `summary_md` → **给人和 RAG**（入索引、导出、作者回看）；**不给写手**（避免复述）

## 4. 卷级前情概要字段

```json
{
  "volume_no": 1,
  "range": [1, 9],
  "arc": "林澈从零里醒来 → 被追索 → 进入第一里，卷末发现自己是被"造出来的人"。",
  "characters": [
    {"name": "林澈", "where": "第一里·地下黑市", "condition": "左臂旧伤未愈",
     "knows": ["自己失忆", "路引被人涂改"], "does_not_know": ["自己的真名"],
     "holds": [], "stance": "躲避追索"}
  ],
  "rules": ["路引决定能否穿里", "零里停留超一个午夜会收走影迹"],
  "long_foreshadows": [{"id": "f1", "desc": "路引背面的涂改", "status": "open"}],
  "turning_points": ["第 3 章 被霍岸拦查", "第 7 章 路引被收走", "第 9 章 发现真名"],
  "ending_state": "失去路引、被全城通缉，但拿到了残图线索",
  "summary_md": "（人读版：200~300 字）"
}
```

为什么卷级要 `characters[].knows / does_not_know / holds`：长篇最常见的崩点是
**信息越权**（角色知道了不该知道的事）与**道具蒸发**（剑不见了），这两件事靠散文摘要查不出来，
靠这三个字段能 0-token 核对。

## 5. 生成方式（增量，不做全量重写）

```
章正文保存
  → arq: chapter_digest            （本章正文 + 账本变更 → 章级 digest）
  → 若本章是卷末（chapter_no % VOLUME_SIZE == 0）
      → arq: volume_digest          （本卷所有章级 digest → 卷级 digest）
  → 若卷末且是第 3 卷的倍数
      → arq: book_digest            （各卷 digest → 全书 digest）
```

- **输入只喂 digest，不喂正文**：卷级输入 = 本卷 8~10 条章级 digest（约 2000~3000 字），
  输出 400 字 → 压缩比约 6:1，且不会因为章数增长而爆预算。
- **增量**：新增一章只重算"本章 digest + 本卷 digest"（卷级每章都重算一次，成本可忽略）。
- **0-token 校验**：字段齐全（events/state_changes/hook 非空）、长度上限、
  `state_changes[].target` 必须能在角色/道具/术语表里找到（找不到 → 标 `new_entities`，不静默）。
- **人读版必须同时在**：`summary_md` 由同一份结构化数据渲染，不单独生成（避免两套口径）。

## 6. 注入策略（写第 N 章时的顺序）

```
【前情 · 全书】      book digest（300 字）        ← 最远，人物弧线/规则
【前情 · 本卷】      volume digest（400 字）      ← 中距，进入状态
【前情 · 最近两章】  章级 digest ×2（400 字）      ← 近距，状态增量 + 钩子
【记忆检索】         RAG 片段（≤800 字）           ← 按本章目标补细节
【上一章结尾】       600 字原文                    ← 语感承接（保留，别删）
```

预算超了就**按层截断**（先砍检索、再砍全书、最后砍卷级——越近越不能砍），并标注"已截断"。

## 7. 与现有模块的接线

| 模块 | 改动 |
| --- | --- |
| `chapters.summary` | 保留（人读/主笔产物）；新增 `chapters.digest_json` 存章级 digest |
| 新表 `book_digests` | (book_id, level=volume/book, range_from, range_to, digest_json, summary_md, updated_at) |
| RAG 索引 | ✅ **v1.62 已落地**：索引对象从"章摘要"升级为"digest 各字段"（事实/知晓/钩子/卷概要分别成 chunk，检索更准）——见 §10 |
| 章后巡检 | 新增"与 digest 冲突"检查（新章否认了卷级 `does_not_know` → 报高危） |
| 骨架体检 | 新增"钩子断裂"检查（上一章 hook 在 digest 里没人接 → 报中危） |
| 写作页 | 左栏「前情」可展开：全书/本卷/最近两章三段，作者可核对（和现在"记忆"面板同一位置） |

## 8. 验收（怎么算做对了）

0-token 可验：字段完整率 100%、注入预算不超、卷级 digest 能在 digest 库里追到本章事件。
LLM 可验（人工盲评）：同一本书第 8 章，**有/没有前情概要**各写一版 → 对比
"道具归属错误 / 信息越权 / 人设漂移 / 钩子断裂"四类硬伤数量（期望显著下降）。

## 9. 需要作者拍板的三件事

1. **卷怎么定**：按固定 N 章切（默认 8~10），还是由主笔排骨架时决定卷边界？
2. **生成时机**：保存即后台自动生成，还是作者手动点「生成前情概要」？
3. **冲突处理**：新章与既有 digest 矛盾时，只报警让作者裁定，还是自动以新章为准？

## 10. 索引与检索消费（v1.62 落地）

**为什么必须升级**：v1.58 让写手 prompt 吃上了 digest，但 RAG 索引里仍只有「章摘要 + 正文尾」——
于是**写手侧读 digest、检索侧读老摘要，两套口径**：同一件事在两处说法不同，检索命中的还是
被 digest 取代掉的旧摘要，预算花了、准确度没涨。

**索引侧（`rag/indexer.py` + `rag/kinds.py`）**

| kind | 内容 | chapter_no | 谁消费 |
| --- | --- | --- | --- |
| `chapter_fact` | one_line + events（谁在哪做了什么→导致什么）+ state_changes（from→to）+ facts_established + new_entities | 章号 | 前情提要 |
| `chapter_knowledge` | knowledge（谁知道了什么、怎么知道的） | 章号 | **知晓范围**（独立段） |
| `chapter_hook` | hook（章末钩子）+ open_questions | 章号 | 前情提要 |
| `volume` | arc + characters（在哪/伤势/持有/知道/不知道/立场）+ rules + turning_points + ending_state | **卷末章号** | 前情提要 |
| `foreshadow_trace` | foreshadow_touched（这条伏笔在第 N 章 埋/推进/回收） | 章号 | 未回收伏笔 |
| `chapter`（保留） | 章摘要 + 正文尾 500 字 | 章号 | 兜底：**没有 digest 的章**（升级不要求先跑压缩） |

三条硬规则：

1. **章号时间闸**：`CHAPTER_SCOPED_KINDS`（chapter / chapter_fact / chapter_knowledge / chapter_hook / volume）
   在检索时一律 `chapter_no < 当前章`。漏一个 kind 就是"角色提前知道后文"的硬伤 —— v1.62 之前
   store 的过滤是按 `kind != 'chapter'` 写的，新增 kind 会自动绕开闸门（已在 `store._chapter_scope()` 收口）。
2. **卷概要取卷末章号**：卷没写完就不该进当前章的前情；`stale=True`（卷边界变过、内容还是旧的）**不索引**。
3. **按章去重**：同一章可能同时命中 fact / hook / 老 chapter 三块 → 只留信息量最高的一块
   （`recall._dedupe_prev`），否则预算全花在重复叙述同一件事上。

**检索侧（`rag/recall.py` · 五段，总预算 ~1900 字）**

| 段 | 取的 kind | 预算/条数 | 兜底 |
| --- | --- | --- | --- |
| 前情提要 `prev` | chapter_fact / chapter_hook / volume / chapter（去重后） | 620 / ≤6 | 按时间序直取最近 3 章 |
| **知晓范围 `knowledge`** | chapter_knowledge | 300 / ≤4 | 无（没有就不显示该段） |
| 相关角色 `characters` | character | 400 / ≤4 | 全部角色卡前 4 张 |
| 世界观 `world` | world | 380 / ≤5 | 世界状态账本前 6 条 |
| 未回收伏笔 `foreshadows` | foreshadow + foreshadow_trace | 220 / ≤5 | 未关闭伏笔前 4 条 |

**索引保鲜**：digest（章/卷/全书）是索引的上游 → `service._reindex_quietly()` 在 digest 生成后
自动入队 `book_reindex`（队列不可用则进程内重建，一本书 ~50ms，**不让索引悄悄过期**）。

**验收（v1.62 实测）**：pytest 414（`test_rag_digest.py` 15 例）· L3 ⑮ 断言「有章节 digest → 必须有
chapter_fact/知晓、书有场 → 必须有 scene 块、recall 必须带 knowledge 段」· live：两章的书索引 46 块，
写第 2 章时前情只到第 1 章（后文泄漏检查为空）。
