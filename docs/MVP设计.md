## 0. 一句话定位

> 多个**角色 Agent** 凭各自目标与记忆，在**共享世界黑板**上自主博弈、涌现出剧情，由**导演 Agent** 用"软引导"掌控节奏、由**护栏**保证长程一致 —— 最终经**成文层**渲染为小说文本。作者与读者均可按需**以人为方式介入**（作者在导演层、读者在角色层）。

---

## 1. 北极星：不变的核心（定基调）

这是一切决策的判据。**未来任何扩展，先问一句"它是否加强北极星？"** 北极星只有一条：

> **在"既有角色自主涌现出的鲜活张力"与"导演可控的叙事收敛"之间，找到可持续的好平衡。**

### 1.1 六条设计铁律（不轻易推翻）

| # | 铁律 | 含义 | 违背后果 |
|---|---|---|---|
| 1 | **涌现优先** | 角色决策是黑盒；导演**只给方向、不给台词**，通过改世界/改感知/改权重来引导 | 变回大纲直写，失去初衷 |
| 2 | **收敛兜底** | 导演 + 三层护栏保证"有张力但不失控、不失控但不枯燥" | 涌现发散成废戏 |
| 3 | **模拟层与成文层分离** | 事件/转录稿 ≠ 小说正文；先模拟出"骨架"，再渲染成文 | "相信角色"但角色说话≠文笔好 |
| 4 | **写前校验** | 一致性护栏在事件**写入前**拦截，不是事后纠错 | 错误污染后续所有回合 |
| 5 | **人在环** | 作者=导演层介入，读者=角色层介入，复用同一套底盘 | 系统封闭，缺共创价值 |
| 6 | **成本意识** | 强模型做演绎、廉价模型做调度/润色/摘要，事件日志保障可回放 | token 爆炸、调优困难 |

### 1.2 防跑偏清单（明确"不做什么"）

> 以下"不做"是**有意的边界**，不是缺点。踩到其中任何一条，都说明我们跑偏了北极星。

- **不做"全自动长篇小说生成器"**：让系统一次性吐几万字的"作品"，违背"涌现+"人共创"的初衷，也落进纯大纲直写的坑。
- **不做"导演替角色写台词"**：一旦导演直接产出角色对白/内心，涌现就死了。
- **不做"单模型直写"**：那不叫 Agent 系统，和普通 LLM 写小说无差别。
- **不做"无限多角色"**：MVP 先 2~3 个角色，把机制跑通，再谈规模。
- **不做"天马行空的世界观"**：MVP 用单场景、单一事件，验证"涌现+护栏"闭环。

### 2.1 两条数据管线（区分"相信的模拟"与"交付的文本"）

| 管线 | 产物 | 消费者 | 是否直接交付读者 |
|---|---|---|---|
| **模拟层** | 事件流 / 转录稿 / 角色决策记录 | 导演、护栏、后续回合 | 否（内部事实） |
| **成文层** | 小说正文 | 读者 | 是 |

- **核心洞察**：模拟层是"发生了什么"，成文层是"怎么把它写出来"。两者分离，才能既保留涌现感、又控制叙事质量与成本。
- **MVP 只做模拟层 + 极简成文层**（把事件流转成可读段落），完整"作家/编辑"双 Agent 进 backlog。

### 2.2 人类介入的两种模式（同一底盘，不同接入点）

| 模式 | 人类位置 | 人类动作 | 对护栏 |
|---|---|---|---|
| **作者创作** | 导演层 | 导演"举手"时，用导演工具介入 | 人类可在作者层强制改 |
| **读者扮演** | 角色层 | 说话/行动/观察 + 自由输入 | 对读者**降级为建议**；世界事实仍硬校验 |

- **MVP 实现"作者创作"模式**（人机共创雏形）；"读者扮演"确认方向后进路线图。

## 3. MVP 范围（第一版做哪些）

### 3.1 功能范围

1. **一个练手微场景**：2~3 个角色 Agent + 单一事件（如前面讨论的"李文背叛陈默"信任主题），跑通完整回合循环。
2. **共享世界黑板**：可初始化、可读写、带感知标签。
3. **每角色信念账本（v0.2 从 backlog 提前）**：记录"该角色知道哪些事实、通过哪件事知道的"（溯源），支撑角色间信息差——信任/背叛场景的核心机制，见 §4.4。
4. **导演 Agent（自动 + 举手）**：自动出软引导；遇分叉/失控/新设定时请求作者介入。
5. **三层护栏（按优先级落地）+ 熔断**：先第3层(世界事实)，再第1层(人设)，第2层(RAG记忆)进第二阶段；打回重演带熔断机制，见 §7。
6. **极简成文层**：把事件流渲染成可读的小说段落。
7. **事件日志（append-only）**：每回合落盘，驱动回放与校验。

### 3.2 明确不做（→ Backlog）

- 作家/编辑双 Agent 成熟成文管线
- 读者扮演（互动剧场）完整交互
- 关系图谱显式建模
- 角色/世界观"卡"模板库与分享生态（UGC）
- 多模态（关键场景插画）
- 类型化导演（悬疑/言情等）

### 3.3 成功标准（MVP 验收）

> 必须**可量化、可对比**，否则不知道北极星有没有保住。

- **涌现有效性**：同一剧本跑 3 次，角色会走**不一样但都合理**的路径（有涌现，不是复读机）。
- **张力质量**：对比"本系统（角色自治+软引导）"vs"单模型直写"，前者在人工盲评中**冲突密度/角色真实感**得分不落下风。
- **收敛性**：无废戏终止——导演能在 N 回合内把事件推向可收束的结局（收束判据见 §6.3）。
- **一致性**：三层护栏下，不出现"死人复活/物品凭空消失/OOC突跳"等**硬伤（要求为零）**；软性偏离允许，见 §7 权衡边界。
- **可回放性（v0.2 新增）**：仅凭事件日志可**确定性回放**整次运行——检验日志完备性，是一切调优的前提。
- **成本**：单回合 token 成本 ≤ **50k**（初始值，可调；廉价模型按折算价计入）。

> 盲评提醒：LLM 评委偏爱长句与华丽辞藻，本系统成文层是极简渲染、天然吃亏——以**人工盲评**为准；若必须用 LLM 评委，需按文本长度归一。

## 4. 数据模型（地基，务求一次定好，避免后期迁移）

> 结构上这些是"地基"，MVP 初期用简单 schema 即可验证，但**语义要按终态设计**，否则后期返工成本高。

### 4.1 角色卡（静态）
```
CharacterCard:
  id, name, 人设summary, 人格特质[], 说话腔调, 核心信条[],
  动态目标[]          # 可被导演调整权重的"动态目标"（调整必须伴随剧情内因，见 §6.1）
  性格底线[]           # 第1层护栏的判定依据
```

### 4.2 世界状态 / 黑板（动态）
```
WorldState:
  settings{...}               # 初始世界观
  facts[Fact]                 # 已确认的世界事实（供第3层校验）
  timeline[EventRef]          # 发生的事件流引用
  envConds[...]               # 环境条件（天气、时局……）
  scene_id, turn              # 当前场景与回合
```

**感知标签（关键）**：黑板状态带"可感知性标签"，角色通过 `visible_to(character_id)` 只能读到自己的子集 → **这是信息差与涌现空间的来源**。
分工（v0.2 明确）：**环境事实**用感知标签；**人际事实**（谁知道谁知道什么）走角色信念账本（§4.4）。

### 4.3 事件日志（append-only，驱动一切）
```
Event:
  id, turn, source(角色/导演/读者/系统),
  type(private_percept|action|environment|director_hint|text),
  payload, world_snapshot, 一致性命中标记
```
> 日志是回放、校验、调优的共同基础；**写前校验**就是在 Event 进库前跑护栏。

### 4.4 角色信念账本（v0.2 提前到 MVP）
```
Belief: {char_id, fact_id, source_event_id, channel(perceived|told|inferred), ts}
```
- 回答"这个角色知道什么、怎么知道的"——**人际事实的认知差（陈默知道吗？李文知道陈默知道吗？）是信任/背叛场景张力的唯一来源**，因此不能放 backlog。
- **溯源（source_event_id）必须有**：没有溯源，"角色为什么知道这件事"在调优期无法解释、无法审计。
- 角色决策时注入的不是全量 `facts`，而是**自己的 Belief 子集 + visible_to 环境子集**——视角隔离由此保证。
- MVP 用 SQLite 表即可；第二阶段在 Belief 之上接 RAG 做相关记忆检索。

### 4.5 记忆 RAG（backlog 主项）
```
Memory: {char_id, type(前缘|评价|情节), text, embedding(vector), ts}
```
- 用 **pgvector** 存，检索相关片段注入角色决策（事实类认知已由 §4.4 信念账本承担，此处只管情节性/评价性记忆）。
- MVP 用简单"近 N 回合上下文 + 关键事件摘要"占位，第二阶段接真 RAG。

## 5. 技术栈 + LangGraph 编排

### 5.1 技术栈定案（合并此前两轮讨论，消除分歧）

| 层 | 选型 | 理由 |
|---|---|---|
| 编排 | **LangGraph** | 状态图天然契合"黑板→角色→黑板"回合循环；已熟练 |
| 状态存储 | **SQLite** | 世界状态/角色卡/感知/事实/信念账本：快、单文件、够用 |
| 记忆 RAG | **pgvector** | 角色记忆向量检索（第二阶段启用） |
| 事件日志 | append-only JSONL / SQLite 表 | 回放与校验基础 |
| 服务/接口 | **FastAPI** | 暴露启动叙事、查看状态、作者介入接口 |
| 结构化约束 | **Pydantic** | 人设卡/世界状态/事件 schema 硬约束，防 LLM 乱写 |
| LLM 路由 | OpenAI 兼容协议 | 强模型=角色演绎；廉价模型=导演/成文/摘要/评估器（控成本） |
| 部署 | Docker (+WSL) | 一致环境 |

> 明确落一条：**MVP 不再引入独立"手写 asyncio 状态机"**（此前的轻框架想法）。LangGraph 已满足需求且是已有技能，避免重复造轮子；真遇到性能瓶颈再议。

### 5.2 LangGraph 图（MVP 节点）

```
 Start
   │
   ▼
[导演计划] ──产出→ [张力场/舞台提示/目标权重/举手请求]
   │                    │
   ▼                    ▼ (出现举手) ──→ ──► [作者介入] ──┐
[黑板·写引导] ◄──────────────────────────────────────────┘
   │
   ▼
[角色感知]  每个角色读 visible_to(self) 子集 + 自己的 Belief 子集
   │
   ▼
[角色决策]  (顺序) 基于人设/信念账本/黑板，涌现行动 ← 第1层人设护栏于此
   │
   ▼
[事件写入]  走三层护栏校验 → 通过写 events / 打回重演(带熔断) ← 第3层护栏于此
   │
   ▼
[黑板·刷新] timeline/environment/belief 更新
   │
   ▼
[成文渲染]  事件流 → 可读段落
   │
   └──────── 是否收敛(对照结局状态集合)？──否───► 回到 [导演计划]
                    │是
                    ▼
                  End
```

**Graph State（Pydantic）**：`world_state`, `events`, `belief_ledger`, `director_hint`, `ending_state`, `converged`。

- **角色决策不做并行（v0.2）**：对话场景里"谁先开口"本身就是戏剧决策——主动权顺序由导演每回合指定（或按简单协议：上一回合的主要行动者本轮后动）。2~3 个角色顺序执行足够，避免过早引入并行复杂度。

## 6. 导演 Agent 的 MVP 策略（软引导）

### 6.1 三把巧劲（改世界/改感知/改取舍）

| 抓手 | 改什么 | 撬动什么 | MVP 实现强度 |
|---|---|---|---|
| 事件注入 | 世界 | 角色处境 | ★★★ |
| 信息曝光 | 感知 | 信息差/筹码 | ★★★ |
| 目标权重调整 | 取舍 | 价值排序/冲突动机（**必须伴随剧情内因**） | ★★ |

- 都是"隐性手法"：改变角色做决策的**处境/视角/权衡**，不让角色说出"导演让我这么做"。
- **约束回拉（硬干预）只在角色 OOC/跑偏时兜底**，尽量少用。
- **权重调整的因果律（v0.2）**：静默改权重等于把手伸进角色脑子里——权重变了，但角色"不知道自己为什么变了"，其推理输出会与内在状态脱节。规则：**每一次目标权重调整，必须同时注入一个该角色可感知的剧情内因**（女儿病重 → 家庭权重上升）。权重是果，事件是因，不能反着来。

### 6.2 举手机制（人机共创）

导演每回合有一个 `tension/divergence` 分（**不由导演自评**——自吹自哨不可信；v0.2 改为独立廉价模型评估器，或纯启发式代理指标：距上次冲突事件的回合数、动作类型分布、目标权重冲突度），出现以下情况即**请求作者介入**：

1. **分叉点**：多种走向都合理但结果迥异；
2. **失控前兆**：角色即将 OOC 或冲突即将失去张力；
3. **新设定缺口**：需要引入世界观级新事物，不该由角色自造。

作者介入后，导演接手"铺张过渡"，把人类的方向投进世界、让角色自己走——**人给的是"牵引力"，不是"遥控器"**。

### 6.3 收束判据（converged 的显式定义，v0.2 新增）

微场景初始化时定义**显式结局状态集合**，导演只能从中选择收束方向，`converged` 不靠感觉：

- 例（信任/背叛场景）：背叛暴露 / 隐瞒成功 / 关系修复 / 公开决裂
- 判定：`converged = 事件流满足某一结局状态的判定条件`，由廉价模型对照结局条件独立判定。

## 7. 三层护栏（实现优先级）

| 优先级 | 层 | 管什么 | 实现 | MVP |
|---|---|---|---|---|
| 1 | 世界事实 | 事实连贯（死人复生/物品消失） | 结构化 facts schema + 写入前查重/查矛盾 | ✅ 做 |
| 1 | 人设 | 性格不跑 (OOC) | 角色卡"性格底线" + 可信度检查器 | ✅ 做 |
| 2 | 记忆 RAG | 前缘/做过的事/说过的话 | pgvector 检索 + 注入决策 | ⏳ 二阶段 |

核心机制：**护栏在事件写入前拦截**，未通过 → 打回角色重新演绎 → 不污染后续回合。

**熔断（v0.2）**：打回重演**最多 2 次**；仍不过 → 降级放行（事件带"瑕疵标记"入库，供调优分析）或升级为导演硬干预兜底。禁止无限重摇。

**权衡边界（v0.2 明示）**：护栏强度与涌现方差天然互斥——反复打回本质是拒绝采样逼角色就范，护栏越严，同剧本多次运行的路径越趋同。验收口径：**硬伤为零，软性偏离允许且正是涌现的证据**。

## 8. 扩展路线图（北极星之下的加装方向）

> 所有扩展都必须满足：**复用同一底盘（角色引擎+黑板+护栏+事件日志），只增加/迁移人类介入点或玩法模块**。

| 阶段 | 形态 | 人类角色 | 复用什么 |
|---|---|---|---|
| ① MVP | 作者+导演+2~3角色涌现 | 作者拍板 | 底盘全量 |
| ② 作者协作工具 | 完善举手-介入流，全局/单场景分层 | 作者=主编 | +事件日志回放 |
| ③ 互动剧场 | 读者作为角色登场（说话/行动/观察+自由输入），护栏对读者降级为建议 | 读者=角色 | +感知标签扩展 |
| ④ 生态/社区 | 角色卡/世界观卡当"mod"分享混搭 | 作者=创作者 | +卡模板库 |

**一句方向判断**：读者扮演（③）是产品**最先形成数据飞轮**的地方——真人选择比纯 agent 更有价值，既是涌现质量测试集，也是导演策略调参金矿。

### 8.1 待探讨钩子（开放问题，不断言，留待后续专章）

> 承接 v0.2 评审后推演出的两个深层问题，暂不落结论，供后续版本单独探讨。

- **信念账本的膨胀与读写压缩（v0.4 候选）**：上百回合后，每个角色的 `Belief` 会累积成大摊子，溯源（`source_event_id`）的信息量会被稀释。§4.4 解决了"写进去 + 溯源"，但未解决"读的时候如何压缩/摘要/过期"。信任/背叛场景短则无碍，长篇及互动剧场必然触发。
- **顺序决策与导演控制权的张力（v0.4 候选）**：v0.2 让"主动权顺序由导演指定"，方向正确，但等于给导演又加了一格控制。需警惕——信息差仍在，可"谁有权先动"已归导演管，多一分收敛、可能少一分涌现。此度值得单独拎出来校准。

## 10. 前端基调（定稿 · 以 `webapp/` 实测实现为唯一权威）

> **基调已落成可运行原型（`webapp/`）**，下述即我方定稿的视觉语言。约定：本项目的 UI 组件、画风、整体前端设计一律以此基调为准，扩展时**只增不改基调**；后续前端（含读者扮演台等远景）都从这里长出去。

### 10.1 一句话基调
**纸墨双主题 + 矿物颜料色系 + 场景级 mood 换肤**——把"舞台导播台"的操控感与"纸墨批阅"的文学气质焊进同一个系统，让用户**看见世界在长出来**。

### 10.2 主题体系：纸 / 墨（不叫 dark/light，这是画风根）
| 主题 | `data-theme` | 底/面板 | 页面底 | 主色（印泥） | 气质 |
|------|------|------|------|------|------|
| 墨（深夜批阅） | `ink`（兼容`dark`） | `--bg-panel:#151922` | `--bg-page:#0D0F14` | `#E8B860` 暗金 ·印泥金 | 暗、密、幕后 |
| 宣纸（白昼批阅） | `paper`（兼容`light`） | `--bg-panel:#FAF6EA` | `--bg-page:#F5EFE0` 宣纸米黄 | `#B5452E` 朱砂 ·印泥 | 亮、纸、文学 |

- `--on-accent`：墨=深棕 `#1A1815`；宣纸=白 `#FFFFFF`（决定按钮文字反色）

### 10.3 色彩系统：传统矿物颜料（状态/语义色统一）
状态色全用国画矿物颜料命名，并配 `-light` 底色变体（墨 0.12 / 宣纸 0.10 的 rgba）：
| 矿物色 | 墨模式值 | 宣纸模式值 | 语义 |
|------|------|------|------|
| 朱砂 | `#D96A6A` | `#B5452E` | 冲突/张力/护栏告警/OOC |
| 石青 | `#6AB5C9` | `#2E7D8F` | 角色行动/事件流入/新生 |
| 石绿 | `#7CB87C` | `#3D8B5E` | 护栏通过/收束达成 |
| 花青 | `#7C9CD4` | `#4A6FCF` | 系统/环境/元信息 |
| 赭金/赭石 | `#E8B860` | `#C77D23` | 导演介入/主 CTA |

### 10.4 场景级 mood 换肤（只换肤色、不动布局）
mood 叠加在纸墨主题之上，只改 `--mood-primary/secondary/light`（背景、描边、强调色），功能色与布局不变；宣纸模式下 mood 另调亮保证浅底可读。
| `data-mood` | 语义 | mood-primary |
|------|------|------|
| `suspense` | 悬疑/推理/谜团 | `#4A5B8A` 深靛蓝 |
| `tension` | 紧张/对峙/危机 | `#8B3A3A` 暗红 |
| `warmth` | 温情/日常/回忆 | `#C47B5A` 暖陶土 |
| `serene` | 宁静/独处/过渡 | `#5A8A7B` 雾绿 |

### 10.5 字体三栈
- **UI/界面**：`Noto Sans SC`（无衬线 · 冷静导播台感）
- **成文正文/阅读**：`Noto Serif SC`（衬线 · 文学纸本感，宋体后备）
- **事件 ID/日志**：`JetBrains Mono`（等宽 · 技术日志感）
词条范式：作者工作台紧凑（13–14px、行高 1.4–1.5 信息密度优先）；读者台宽松（15–18px、行高 1.8–2.0 阅读舒适优先）；对话用"角色名左标签 + 引号"不用聊天气泡（避 IM 感）。

### 10.6 布局骨架（导播台）
- **作者工作台**：顶栏（品牌 + 场景回合 + mood 切换 + 墨/纸切换 + 运行态）+ 三栏（左角色栏 / 中央主舞台 / 右导演控制台）+ 底部时间线
- **主舞台双标签**：世界黑板 ↔ 成文预览（含角色小头像对话、章节字数、上一/下一章）
- **导演控制台**：张力指数 + 导演提示 + 介入工具 + 举手请求 + 护栏状态
- **读者阅读台**：宣纸单列沉浸 + 对话头像 + 底部细进度条 + 沉浸切换
- **书架概览台**：左书签栏（书架/本书工作区导航）+ 右主导航（概览/设定/人物/大纲/伏笔/章节/记忆包/体检）+ KPI 卡（健康分环形图）+ 章节目录、待办、金句池、热度热力

### 10.7 绑"可看见的涌现感"的核心组件
- **角色卡片**：立绘 + 情绪条（"情绪水位"百分比 + 平静→爆发刻度）+ 目标权重 + 信念账本（获知渠道标签 `亲见`/`推测`/`被告知`）
- **世界黑板**：环境事实（带角色可见度 `陈默✓ 李文✗`）+ 当前回合事件卡（`E-042` + 感知标记）+ 角色状态摘要
- **时间线**：回合节点（`T-01 雨夜归家`…）+ 回放控制（⏮◀▶⏭）+ 事件类型图例（行动/对话/冲突/信息）
- **角色画风**：立绘为像素风/二次元头像缩略（当前 `assets/portrait-*.png`），情绪态用配色（如紧张=朱砂、平静=石绿）

### 10.8 权威源（实现基准）
- 主题与 mood 变量唯一源：`webapp/css/tokens.css`
- 视图形态基准：`webapp/index.html`（作者工作台 + 读者阅读台）、`webapp/dashboard.html`（书架概览）、`webapp/characters.html`
- 未来基调演进：改基准实现并回填本节；**任何需求不得绕过此基调另起画风**。

## 12. 创作引擎 skill / prompt 生态规划（backlog，v0.3 新增）

> **方向**：把"导演智慧 / 角色演绎 / 润色审校 / 世界观"封装成可复用的 skill / prompt——这是让本项目从"一次性 demo"进化为"可组合、可复用、可调教的创作引擎"的护城河。
> **时机**：等应用主体搭建起来、运行时需要这些能力时再逐个落地；当前仅登记规划，不落地文件。

### 12.1 生态地图（按"角色引擎 → 导演 → 成文 → 世界"四线）

| 线 | Skill / Prompt 名 | 内容来源 | 优先级 |
|---|---|---|---|
| 角色 | 角色卡生成器 | 五维人设 + Soul Field → `CharacterCard`（对齐 §4.1） | ★ 第一批 |
| 角色 | 角色演绎 | 角色 Agent 感知→决策→行动核心 prompt（对齐 §4.4 信念账本） | ★ 第一批 |
| 导演 | 导演调度 | 三把巧劲 + 举手机制（对齐 §6.1·§6.2） | ★ 第一批 |
| 导演 | 张力场/节奏判定 | 温度档、钩子、信息差判断（独立评估，对齐 §6.2） | ★ 第一批 |
| 成文 | 骨架→正文（作家） | 文笔原则 + 反 AI 文风清单 | ★ 第一批 |
| 成文 | 一致性审校（编辑） | 长文状态文件 + 三层护栏（对齐 §7） | ◐ 二批 |
| 世界 | 世界观卡生成器 | 三层规则世界观 | ◐ 二批 |
| 读者 | 读者扮演动作选择器 | 互动剧场"说话/行动/观察" | ○ 远期 |

### 12.2 首批 5 个核心骨架（暂定，按此进入时再细化）

1. `角色卡生成器` —— 从一句话人设扩成五维 + Soul Field 的结构化 `CharacterCard`
2. `角色演绎` —— 注入人设/信念账本/黑板子集，产出角色自发行动
3. `导演调度` —— 出软引导 + 举手请求 + 结局状态收敛选择
4. `张力场判定` —— 独立评估当前张力/divergence，供导演决策（不自评）
5. `骨架→正文` —— 事件流渲染成可读小说段落（对齐极简成文层）

### 12.3 落地约定

- **形态**：项目级 skill（`.trae/skills/<name>/SKILL.md`），随项目走、方便反复调教；未来可固化升级为独立插件分享。
- **创建方式**：一律用 **`skill-creator`**（TRAE 新建 skill 的专用工具）来建立，不手写 SKILL.md 骨架，保证结构规范、便于调教。
- **story-craft 定位（防混淆）**：`trae-remote-official:story-craft:story-craft` 是 **TRAE 官方插件**（写作技法知识库，五维卡/张力分层/反 AI 味文笔），非本项目系统资产。它作为**参照素材**：其张力分层、反 AI 味文笔、"契约造戏剧"理念，将来**移植进**本项目的"导演调度 / 张力场判定 / 骨架→正文"等系统 skill 的内部规则；运行时**不直接依赖** TRAE 插件。
- **内容语言**：中文正文 + 英文 `description`（贴合调教习惯，又不影响触发判断）。
- **不塞任务数据**：skill 只封存可复用的流程/约束/准则，不含一次性结果、路径、私有数据。
