# 优化方案 S3 · 全局结构与张力（Global Tension / Structure）

> 版本 v0.1 · 2026-09-13
> 上位文档：`docs/写作痛点清单与优先级.md`（S3 · 全局结构 / 张力失衡，等级 S）
> 定位：**先做轻量"看得见"**（章级张力标注 + 伏笔网络 + 结构诊断），**不做自动调度**（见 §6）。
> 目标：把"情节挺好但太平了"从**读者抱怨**变成**可量化的曲线 + 可解释的诊断项**，让作者一眼看到全书节奏塌在哪一章。

## 2. 目标（轻量版边界）

**做**：
1. **章级张力标注**：每章给出 `tension_avg` / `tension_peak` / `trend` / `turns` / `prose_chars`；
2. **全书张力曲线** + 峰值章/谷值章/标准差；
3. **结构诊断（0-token、可解释）**：平铺 / 无上升 / 高潮缺失 / 无喘息 / 伏笔逾期 / 埋收失衡 / 光秃场景（§3.3）；
4. **伏笔呼应网络**：埋设章 → 期望回收章的关系 + 逾期清单；
5. **一个接口 + 一个前端区块**（不引入图表库）。

**不做**（本期）：张力驱动的自动调度（低张力→自动加戏）、LLM 二次评估张力、跨书对比、时间轴动画、导出报告。

## 3. 设计

### 3.1 数据落点：零新表（与 S1 相反的理由）

| 数据 | 来源（既有） | 说明 |
| -- | -- | -- |
| 回合张力序列 | `simulation.state_json` → `turn_archives[].tension/tension_trend` | 已完成场景同样有（`ended=True` 仍保留归档） |
| 场景→章归属 | `scenes.chapter_id` / `chapters.order_no` | 既有四层结构 |
| 正文体量 | `scenes.final_prose` | 既有 |
| 伏笔网络 | `foreshadows.buried_scene / expected_close_scene / status / related_char_ids` | 既有三态账本 |

**新增读取口**：`repo.list_sims_by_book(book_id) -> [{id, scene_id, ended, updated_at}]`（复用现有查询形状，去掉 `ended` 过滤；含内存态兜底）。

### 3.2 章级张力算法（0-token）

```
scene.tension_avg  = mean(该 scene 最新 sim 的 turn_archives[].tension)      # 无归档 → None
scene.tension_peak = max(同上)
chapter.tension_avg = mean(其 scenes 的非 None tension_avg)                    # 无 → None
chapter.tension_peak = max(其 scenes 的非 None peak)（无 → None）
chapter.trend = 末回合 tension_trend（无 → "flat"）
```

- **只取每个 scene 最新一个 sim**（重跑场景时旧 sim 作废，避免重复计数）；
- 无张力的场景 **不按 0 计入**（0 会把"未推演"误判成"平淡"）；
- 曲线按 `chapters.order_no` 排序，缺值章在曲线上标记 `null`（前端断线显示）。

### 3.3 结构诊断规则（全部确定性、每条带"扣分 + 证据"）

| 规则 | 判定 | 文案 |
| -- | -- | -- |
| R1 平铺 | 有张力章 ≥3 且 `std(avgs) < 8` 且 `mean(avgs) < 45` | "全书张力长期贴地且波动小 → 缺起伏" |
| R2 无上升 | 存在连续 ≥3 章 `avg` 不升（Δ≤0） | "第 X-Y 章连续走平/回落，缺推进感" |
| R3 高潮缺失 | 峰值章不在**后 1/3**，或末章 `avg < peak×0.6` | "峰值出现在前段，结尾偏平" |
| R4 无喘息 | 峰值后无任何章回落 ≥15% 峰值 | "峰值后一路贴峰，读者无喘息位" |
| R5 伏笔逾期 | `expected_close_scene` 所属章序 ≤ 最新有正文章序，且状态未 closed | "N 条伏笔已过期未回收：…（列出）" |
| R6 埋收失衡 | `open ≥ 5` 且 `open > closed×2` | "埋设远多于回收 → 呼应会散" |
| R7 光秃场景 | 有 `final_prose` 但无张力记录的场景数 > 0 | "N 个场景有正文无推演记录（张力未采集）" |

- `structure_score = 100 - Σ(规则扣分)`（R1 20 / R2 12 / R3 15 / R4 8 / R5 15 / R6 10 / R7 5，下限 0）；
- **与 dashboard `health` 并增不替换**：`health` 管"完成度"，`structure_score` 管"节奏"。

### 3.4 伏笔网络

```json
{
  "nodes": [{"id","type","text","status","buried_chapter","expected_chapter","related_char_ids","overdue"}],
  "edges": [{"from_chapter","to_chapter","foreshadow_id"}],
  "overdue": ["..."]
}
```
（scene_id → chapter_id → order_no 的映射在服务层一次性建好传入，引擎保持纯函数。）

### 3.5 API（并增）

`GET /api/v1/books/{book_id}/global-view` →
`{book_id, curve:[{chapter_id,title,order_no,tension_avg,tension_peak,trend,turns,prose_chars,status}], summary:{mean,std,peak_chapter,flat_chapters}, diagnostics:[{rule,severity,deduct,title,detail,evidence}], foreshadows:{nodes,edges,overdue}, structure_score}`

### 3.6 前端（零依赖）

DashboardPage 增「全局张力」区块：**纯 SVG** 折线（宽自适应、缺口断线、峰值点标注）+ 诊断清单（severity 着色）+ 伏笔网络摘要（埋/收条数 + 逾期前 3 条）。不引入 chart 库（保持依赖最小）。

## 5. 验收标准（可测）

1. **派生正确**：构造 3 章（张力 20/50/80）→ 曲线 = [20,50,80]，`peak_chapter` = 第 3 章；
2. **R1 平铺**：3 章张力 [30,32,31] → 命中 R1，`structure_score = 80`；
3. **R3 高潮缺失**：峰值在第 1 章且末章 < 峰值×0.6 → 命中 R3；
4. **R5 伏笔逾期**：`expected_close_scene` 落在已定稿章之前且未 closed → 进 `overdue`；
5. **不误伤**：只有 1 章 / 无张力记录时**不报** R1-R4（样本不足不下结论），但 R7 会如实提示"有正文无推演记录"；
6. **回归**：全量 pytest 全绿；真实书（`book-rain` 等 4 本）实测接口返回结构完整。

## 6. 明确不做 / 触发条件

| 不做 | 原因 | 触发何时纳入 |
| -- | -- | -- |
| 张力驱动自动调度（低张力→自动加戏/调权重） | 先要"看得见"，再谈"自动动"；否则容易变成新的黑箱 | 曲线与诊断被作者实际用起来后 |
| LLM 二次张力评估 | 现有 `director` 已逐回合评估；再加一层是重复收费 | 发现确定性张力与实际阅读体感偏差大时 |
| 跨书对比 / 题材基准线 | 样本不足，易误导 | 有 ≥5 本完稿书时 |
| 图表库（echarts/d3） | 折线 + 清单用 SVG 足够，避免依赖膨胀 | 需要交互式缩放/多序列叠加时 |
| 张力写回账本（新表） | 派生即可，写回会引入一致性维护成本 | 需要"张力历史趋势（多次修改对比）"时 |
