# 优化方案 S2 · 角色口吻一致性（Voice Consistency）

> 版本 v0.1 · 2026-09-13
> 上位文档：`docs/写作痛点清单与优先级.md`（S2 · 人物口吻漂移）
> 依赖现状：`engine/prose.py`（`_characters_block` / `_DRAFT_PROMPT` / `_REVIEW_PROMPT` / `_VERIFY_PROMPT`）、`schemas/models.py::CharacterCard`、`engine/character.py`（正确读法范本）、`service.py`（`prose_draft` / `prose_review` / `prose_verify`）、`prose_notes.payload_json`

## 2. 目标

- **注入**：写手拿到"谁在演 + 怎么说"的可执行锚点（腔调原文 + 特质 + 底线 + 作者演绎要求），而不是一句"符合角色性格"。
- **回环**：体检能指名道姓指出"这句不像 Y 说的"，并给证据原句；质检把口吻偏离写成风险。
- **可审**：口吻结论落 `prose_notes.payload_json`，作者可查、可手改；不改表结构。
- **不误伤**：润色师"只改写法不改事实"的边界不破；口吻整改走"体检 → 作者确认 → 定点重写"。

## 3. 设计方案

### 3.1 字段对齐（P0 · 已落地）

`_characters_block` 改读真实字段，输出结构化锚点：`- 林尘：落魄剑修；特质：隐忍、护短；腔调：话少，短句，常以「嗯」应人；底线：不伤妇孺`。空卡显式标注"（未填角色卡：请按名字自设一致腔调，勿套用通用音色）"，不再静默假装有设定。

### 3.2 写手 prompt 增「口吻锚点」段（P0）

现状 `_DRAFT_PROMPT` 只有一句"符合角色性格和腔调"，属于**口号而非约束**。改法：

- 锚点由 3.1 提供（逐字进 prompt）；
- 追加**反同质**硬要求：本场多角色对话，禁止各角色共用同一句式/口头禅，语气词必须可区分；
- 追加**称呼一致性**约束：角色互称须与卡内关系一致（与账本 `term` 类呼应，避免"林兄/尘哥/林尘"乱跳）。

### 3.3 体检注入角色卡 + schema 增 `voice_findings`（P0）

- 签名：`review_prose(llm_client, scene, text, characters=None)`
- `REVIEW_SCHEMA` 并增：

```json
"voice_findings": [{
  "char": "str 角色名",
  "evidence": "str 正文原句（必须逐字摘录）",
  "issue": "str 哪里不像（语气词/句长/称呼/用词层级）",
  "suggestion": "str 改成什么更贴卡"
}]
```

- 校验器：`voice_findings` 必须为数组；**无 `evidence` 的条目直接丢弃**（防幻觉的关键闸门）。
- 服务层 `prose_review` 把 `get_scene_characters(scene_id)` 传进去（该函数已存在，见 `service.py:80`）。
- 落点：editor note 的 `payload_json` 增该字段，"正文协作"面板可加"口吻"折叠区（可选）。

### 3.4 质检增 `voice_risks`（P1）

`VERIFY_SCHEMA` 并增 `voice_risks`（**并增不改旧字段**，与 S1 扩 `state_deltas` 同一套路；validator 同步加键检查）：

```json
"voice_risks": ["str 角色名：偏离点（引用原句）"]
```

- **不新增 LLM 往返**：同一次 `verify_prose` 顺带产出。
- 风险：必填键已到 6 个，模型漏字段概率上升 → 校验器的"缺字段"反馈必须**列出缺失键名**（现为笼统提示）。

### 3.5 0-token 口吻先验（P1，与 A3 共享）

不依赖 LLM 的确定性检查，跑在 draft 之后、体检之前（成本 0、可单测）：

- 对话句中"了/是/的"密度、平均句长、破折号/省略号计数 → 超阈值标红；
- 各角色**语气词集合**重合率 → 超阈值判"疑似同质"；
- 称呼表：正文中"林尘/林兄/尘哥"的使用是否与卡内关系一致。

> 这条与 **A3（AI 腔同质）** 的技术底座是同一个校验器，建议 A3 展开时**共用**，避免造两套。

### 3.6 数据落点

| 数据 | 落点 | 说明 |
| -- | -- | -- |
| 口吻体检明细 | `prose_notes.payload_json.voice_findings` | 复用迁移 0010 已有字段，**不新增表** |
| 口吻质检风险 | `prose_notes.payload_json.voice_risks` | 同上 |
| 角色声线档案（跨场景累积） | ❌ 本期不做 | 见 §6 |

## 5. 验收标准（可测）

1. **注入**（已有用例）：角色卡含 `voice`/`traits`/`bottom_lines` → 写手 prompt 逐字包含；空卡 → 明确标注"未填角色卡"。
2. **体检回环**：给一段"林尘突然滔滔不绝"的正文（卡内 voice=话少短句），`review_prose` 的 `voice_findings` 必须命中该角色，且 `evidence` 是正文原句。
3. **无证据不成立**：LLM 返回缺 `evidence` 的条目 → 校验器丢弃，不写进 note。
4. **质检并增**：`verify_prose` 回退值含全部 6 键（含 `voice_risks`）；缺键时反馈列出缺失键名。
5. **回归**：pytest 全绿；S1 的 `state_deltas` 记账、幂等保存行为不回退。

> **2026-09-13 实测（真实 LLM · 阿里云百炼 · 雨夜书房 scene-betrayal-night）**
> 1. **注入**：3 张卡（陈默/李文/周婶）在 `_characters_block` 中逐字渲染出「腔调/特质/底线」；修复前全部是"（无详细设定）"。
> 2. **写手**：真 LLM 初稿里陈默短句（"夹层里。"）、李文长句试探、周婶收尾一句点破 —— 三把声线可区分。
> 3. **回环**：喂一段"陈默滔滔不绝"的越界正文 → `voice_findings` 命中 `陈默`，附逐字原句证据与改写建议，editor note 的 `payload_json` 已落库。
> 4. **验收口径**：§5 第 1-3、5 条已通过；第 4 条（`voice_risks`）**已随 step4 通过** —— 真 LLM 实测命中 1 条越界台词（char=陈默、逐字原句、并增到 `risks`），note 的 `payload_json` 已落 `voice_risks`。

## 6. 明确不做 / 触发条件

| 不做 | 原因 | 触发何时纳入 |
| -- | -- | -- |
| 角色声线档案表 | 现阶段"卡 + prompt"够用，跨场景累积声线属过度设计 | 出现"成长后口吻演化"需求时 |
| 口吻向量/相似度模型 | 引入 embedding 依赖，收益不确定 | A1 接 RAG 时一并评估 |
| 逐句强制重写 | 破坏"作者掌控"，成本高 | 作者确认"整段声线失败"时手工触发 |
| 润色师改口吻 | 与"只改写法"边界冲突 | 若体检口吻整改被高频采纳，再评估独立"声线润色"角色 |
